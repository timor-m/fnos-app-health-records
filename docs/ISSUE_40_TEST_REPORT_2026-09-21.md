# Issue #40 实现与测试报告

日期：2026-09-21。测试对象为 main 分支、基线 8ff2e1d 上的当前工作区，包含并保留此前已暂存的成员共享、备份恢复和回收站改动。本轮未提交、推送、创建 PR、发版或操作真实用户数据库。

## 实际实现

- 报告原件增加「补充报告页」，显示目标报告与成员，支持上传、拖入、拍照、现有授权目录导入、逐文件进度/重试、PDF 后台分页、选页、排序和旋转。
- 草稿与正式页面分离，文件受账号、报告和批次绑定；只允许管理者操作，不授予管理员隐式档案权限。可靠归属冲突或近似重复进入确认，可排除部分疑点页、确认保留页或放弃。
- 完全重复图片按文件哈希跳过，PDF 加源页号判断；全重复批次不改报告、不调用 AI。新增页面保持原 report_id，原页面 ID、归属和日期不变。
- 复用 processing_jobs 的租约、队列和 AI 规划/分块/证据校验；已有有效 OCR 复用，缺失或最新 OCR 任务无有效结果时补齐。AI 使用整份有效报告内容。
- 发布事务校验旧记录完整性、人工覆盖、稳定页面来源和输入版本。手动删除指标有来源抑制记录；损害旧记录的候选整体回滚，拒绝候选保留审计但不作为成功缓存反复复用。
- 权限撤销、并发页面操作、旧租约回调、取消和版本改变均有服务端保护。已提交识别结果但索引失败时单独恢复索引，不重复调用 AI，也不提前显示完成。
- 完整备份/恢复、存储迁移与 GC 纳入未完成批次文件；详情可区分原件版本与成功识别版本。AI 未启用时保留原件/OCR及旧结果，并释放批次锁。
- 部分 PDF 选页下载只返回已发布页，避免未选页通过原件接口泄露；永久删除同步清理已放弃批次文件。形态发现允许重建自动追踪关系，同时保留人工分组和原有事实。

主要实现文件：`page-append.service.ts`、`page-append-lock.service.ts`、`page-append-result-guard.service.ts`、`ReportPageAppend.vue`，以及现有 job-runner、AI persistence、上传、目录授权、GC、报告和人工校对服务的接入点。详细设计和使用限制见 [REPORT_PAGE_APPEND.md](REPORT_PAGE_APPEND.md)。

## 消融与简化复核

在临时数据库中移除“已发布记录基线”后，缺失旧指标的候选可通过校验；恢复基线后明确拒绝，事务回滚后旧指标仍在。对应自动化消融用例通过，保留此保护。

目录解析去掉未使用的成员/请求编号参数，仅负责返回已授权来源；文件复制继续复用现有受限复制函数。批次放在现有 reports/thumbnails 根目录，备份/迁移沿用既有目录机制。未引入新依赖、第二套任务调度器或临时报告模型。

## 未执行检查与剩余风险

- 未连接真实 fnOS、Docker 设备或真实用户数据库；未实测手机相机、fnOS 授权弹窗、不同浏览器 WebView。
- OCR/PDF/缩略图与 AI 调用使用可控替身。真实多页 PDF、HEIC 解码、复杂版式 OCR 和外部模型返回质量需要部署环境验收。
- 未做 1000 文件、2 GB、10000 页极限压力测试，也未模拟设备真实断电；使用数据库重启、过期租约、故障注入及迟到回调验证恢复逻辑。
- 近似重复和身份提示依赖可提取的文字及可靠标签，不能识别所有模糊扫描或缺少身份信息的报告；最终归属仍由管理者核对。
- 完整性保护采用保守比较，AI 对旧事实的合理改写也可能被拒绝。此时保留旧结果，允许重试或保留原件/OCR后人工校对。
- 未正式编号的数据库草案仍需在用户授权发布时，相对正式发布基线统一整理并执行发布前检查。本轮未打 FPK、构建 Docker 镜像或执行真实数据库升级。

## 补页完整性校验调整

单独上传与补页原先对“候选未匹配”采用不同处理：补页直接失败。本轮移除这条整批拒绝规则，补页通过现有 supplement 单元对遗漏片段补识别一轮（概览模式也适用），其余单独上传策略不变。

补识别后仍未覆盖的候选或证据过滤提示，直接从已有候选和单元审计读取，显示“补页完成，部分内容待核对”及本次识别页码/原因。发布继续执行旧记录、人工覆盖、抑制记录、权限和版本保护；主请求失败、无有效结果、损害旧记录均不发布。未新增数据库字段、状态、任务队列或循环补识别机制。

新增回归覆盖：只补遗漏片段一轮、补识别成功后无待核对提示、仍有疑点时保存可信结果并释放批次锁、无可验证结果仍失败、UI 不将待核对状态显示为全部成功。消融复核继续保留已有旧记录保护测试。真实报告未被修改或自动重试，真实 OCR/AI 返回仍需用户重试验收。


## 删除整份报告不再受补页锁限制

新增合成数据测试覆盖 OCR/AI 执行期间删除、恢复后拒绝迟到 AI 结果、失败批次删除、无权用户拒绝、删除失败回滚及永久删除清理补页文件。服务端全量 831 项、UI 45 项、类型检查、构建和差异检查通过；未删除真实报告，未做真实外部 OCR/AI 请求中断实测。
