# 档案存储迁移

适用于 fnOS 应用。应用程序及 OCR 环境保留原位置，数据库、报告原件、缩略图和业务配置一起迁移到另一处本地存储空间。不限定 RAID；任何存储都不能替代独立备份。

## 操作

1. 先完成独立备份，停止上传新报告。
2. 在飞牛应用设置中，给应用授权目标目录的读写权限。个人“从 NAS 导入”授权不能代替应用级授权。
3. 管理员进入“我的 → 存储设置”，选择目录，点击“检查并迁移”，检查空间和文件数量后确认。
4. 迁移会暂停所有用户的业务访问，等待当前任务结束，然后复制并校验。页面可刷新或关闭，任务仍在后台运行。
5. 完成后返回应用，确认报告原件、指标、模型配置及新增报告正常，再另行安排旧数据清理。应用不会自动删除源目录或失败副本。

目标必须可读写、空间充足且不与原目录嵌套；目前允许 ext4、Btrfs、XFS 本地文件系统，不支持 SMB/NFS 等网络挂载。应用按应用 ID 创建 `fnos-app-health-records` 子目录，不再使用 UUID 作为目录名。同名目录已存在时拒绝新迁移，不覆盖其中的文件。旧版本创建的 UUID 目录仍可读取和继续原任务，不会自动重命名。

## 清理旧档案副本

迁移完成后，存储设置会提醒旧副本仍保留。确认新档案正常且已有独立备份后，点击“检查并清理旧副本”，查看旧路径、文件数量及大小，再确认删除。无需重启。

- 只逐个删除本次迁移清单内、内容仍与迁移时一致的旧文件：数据库、原件、缩略图、报告导出及上传暂存文件。不递归删除整个旧目录，空目录可能保留。
- 运行配置、密钥、OCR 环境及备份始终保留；新建或内容已变化的文件不删除，新档案不受影响。
- 删除不可撤销，只能依赖独立备份恢复。发生中断时，未处理的文件保留，可检查后重试；页面反馈已删除和跳过的数量。
- 迁移未完成、新档案不可用、目录身份变化或发现旧数据库使用痕迹时拒绝删除。只允许飞牛管理员操作，Docker 不提供此模块。
- **历史迁移没有文件校验清单时，不开放一键清理**，页面会明确说明。不能靠升级补造历史校验记录，也不要直接删除原运行目录。

## 中断与故障

- 切换前可以取消，仍使用原目录；已复制文件保留。
- 应用重启后，活动迁移不会自动继续。管理员通过原应用入口进入维护页，确认继续或取消。
- 切换后不能取消或自动回到旧副本，避免新数据丢失。继续操作只校验当前档案，不再覆盖为旧副本。
- 存储空间离线或身份不匹配时停止业务访问，不创建空数据库；恢复挂载和授权后由管理员继续处理。
- 源文件变化、目标混入其他文件、空间不足等都会停止迁移。失败副本保持原样；确认原因后可重试，必要时取消并创建新任务。
- 本机位置配置、迁移日志与清理清单不进入业务备份，恢复业务备份不会覆盖它们。不要手动修改这些内部文件。

## 部署边界

- Docker 不提供此模块（包括入口、页面与存储设置 API），继续使用 `/data` 挂载，由宿主机调整数据卷。
- 升级不会自动迁移，查看设置也不会修改目录。
- **重装系统/应用后的档案接管尚未完成**。当前迁移不能视为脱离原运行目录的灾难恢复方案，请保留独立备份及原运行目录。

完整真机及断电/撤销授权等故障验收进度见 [阶段验收](QA-storage-migration.md)。
