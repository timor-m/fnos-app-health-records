## 接口与运行约定

### 读取接口

所有接口按当前登录用户实时校验成员权限；个人关注及自定义分组在查询时叠加，不进入成员公共快照。

| 接口 | 参数和结果 |
| --- | --- |
| `GET /api/trends/snapshot` | `memberId` 必填；可带 `query`、`group`、`attention`。返回版本、状态、完整分组目录、关注首批和首个非空普通分组首批，首批各 12 项。 |
| `GET /api/trends/snapshot/status` | `memberId`；返回已发布版本、目标修订及 `building/ready/updating/retrying` 状态，不计算趋势。 |
| `GET /api/trends/snapshot/series` | 同上，另可带 `section`、`pin=all/only/exclude`、`cursor`、`version`、`limit`；默认 12、最多 48。返回摘要、数量及下一个不透明游标。 |
| `POST /api/trends/snapshot/charts` | JSON `{memberId,version,keys}`，一次最多 12 个稳定序列键，返回完整绘图历史。 |
| `POST /api/trends/snapshot/details` | 参数同 charts，返回排除记录等整理详情，来源报告/原图沿用已有按需读取接口。 |

序列键为指标身份与单位的 JSON 二元组，不以数组位置对应。图表和详情必须携带快照版本；游标同时绑定用户、成员、快照、查询条件及关注状态，客户端不得自行拼接或复用到其他查询。

`attention` 支持 `all/attention/unflagged/abnormal/near_boundary`。分组选择按目录关系解析指标集合；同一指标的不同单位保留为不同序列。目录中的指标数与卡片序列数分别统计，普通视觉分组排除关注区已有序列。搜索、状态筛选、总数和分页均基于完整服务端快照。

参数错误 400；未登录/无权访问 401/403；成员不存在 404；版本或游标作用域变化 409。客户端权限拒绝时清除已展示数据，暂时断网则保留可读内容并允许重试。兼容旧完整接口 `/api/trends` 仍返回全历史数组（或 `includeGroups=true` 的组合对象），明确要求成员；未就绪返回 503，不触发现场计算。新页面使用拆分接口，不依赖该大响应。

### 更新与部署

- 同成员变更合并；只读 worker 读取一致事务视图，主进程按租约及目标修订校验后一次发布。不覆盖计算期间发生的新变更。
- 单进程协调器一次处理一个成员任务，超时 180 秒，失败按 500ms 起指数退避至 30 秒上限，重启恢复中断租约。批量归一化或存储维护期间暂缓领取任务。
- 普通编辑可继续读取上一份完整快照并提示更新中；删除、回收站及归属转移立即屏蔽受影响旧快照。权限始终实时判断。
- 算法版本不一致、字典/分类规则变化、无法可靠确定增量范围、恢复备份时执行重建。派生表通过既有启动备份和幂等结构补齐机制处理，本次不递增应用或 schema 编号。
- 生产 worker 为独立 `trend-snapshot-worker.mjs`，随 FPK/Docker 的 server 目录打包；不依赖 tsx 或开发源码。关闭/切换存储先终止旧 worker，其结果不能写入新存储。
- 旧版本清单、未引用序列和删除成员的派生数据会清理。无需额外 Redis、外部任务队列、前端全量副本或独立图表状态框架。
