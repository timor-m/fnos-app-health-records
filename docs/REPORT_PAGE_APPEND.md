# 补充报告页（Issue #40，未发布）

在报告详情「报告原件」区域选择「补充报告页」，打开桌面侧边抽屉或手机底部抽屉。关闭抽屉保留文件选择和批次进度，重新打开可继续；关闭不会取消后台任务。入口按钮会显示待提交、OCR 中、AI 整理中、需重试、待核对或已完成。抽屉展示准备页面、识别文字、AI 整理、完成四个阶段，OCR 使用实际已识别页数，AI 使用现有处理单元计数，不估算百分比；内容补识别可能增加处理总数。选择文件并预览不代表已提交，须点击“补充并识别”。批次的提交、重试及完成操作固定在抽屉底部，处理中可以收起弹窗；成功后明确提示页面和整理结果均已保存。补页状态每 3 秒刷新，阶段变化会同步详情页任务区与报告结果；OCR、AI、待确认和失败均显示具体提示。离开页面暂停前端轮询，返回后重新读取，后台任务继续执行。管理者可上传、拖入文件、拍照或从现有授权目录导入；Docker 使用已有 IMPORT_ROOTS，不能填写任意服务器路径。补充记录仍是独立的文字/图片记录，不参与 OCR 或 AI。

## 使用流程

1. 上传文件，每文件显示上传进度；单文件 40 MB，单批 1000 文件、2 GB。PDF 后台读取页数并生成分页预览，单批最多 10000 页。
2. 勾选 PDF 页或图片、调整新增页顺序与旋转角度，点击「补充并识别」。已有页面保持原 ID、顺序和归属。上传失败保留批次，重试只发送未完成文件；刷新后可重新选择原文件继续上传。
3. 新页先在草稿中 OCR；已有有效 OCR 不重跑，缺失的旧页 OCR 会补齐。同一报告或批次的完全重复图片按文件哈希跳过；PDF 按文件哈希和源页号判断。全部重复时不修改报告或调用 AI。
4. 同报告/同批次近似文字重复，或姓名、报告编号、同种日期等可靠标签不一致时，暂停在待确认状态。管理者对照原件后排除部分页面、确认保留页或放弃；不会自动删除相似页，也不会更换成员或推断归属。
5. 页面发布到同一报告后，复用现有整份报告 AI 规划、分块、证据校验及归一化流程。只调用旧页 OCR 加新页 OCR，不创建临时报告或合并 PDF 文件。
6. 新结果通过校验后，结构化数据在一个短事务中发布。旧指标丢失、原来源值改变或人工校对受损时整次回滚，保留旧结果。未覆盖候选不再直接判整批失败：补页任务复用现有遗漏片段补识别（概览模式也执行一轮），已成功单元继续复用。补识别后仍有疑点时，发布通过证据和旧记录保护校验的可信结果，显示“补页完成，部分内容待核对”，列出本次识别页码及原因。没有可验证结果或主识别请求失败时仍保留失败状态。原报告日期、元数据和人工校对不被补充流程改写，手动删除的指标有来源抑制记录。

适用于同一份报告漏扫、漏传的页面；不同日期的独立检查应新建报告。选取部分 PDF 页后，正式原件下载只导出已发布页，不能下载到未选中的源页；原始 PDF 保留用于追溯和备份。导出复用现有按需 PDF 生成机制，不作为补页入库步骤。

AI 未启用时保存原件和 OCR，并释放批次锁。界面明确提示当前仍是上一版结果。稍后手动 AI 使用当前全部页，并继续执行旧记录保留校验。已发布但失败的批次可以重试，或选择「保留原件与 OCR，结束本次识别」。未发布批次可以放弃；已发布页面不通过“放弃”删除。

## 持久化与并发

- 未编号 `page-append-draft.ts` 新增批次、文件、草稿页及指标来源抑制表。应用保持 0.2.10，schema 保持 v17；新库、已有库和恢复数据库均安装草案，已有库升级前自动备份。
- 使用现有 `processing_jobs`，批次类型 `page_append`，流水线 `page-append-v1`。准备、OCR、AI 分阶段保存检查点，重试沿用失败任务及其已完成 AI 单元；没有第二套调度器。网络/服务错误保留已完成单元；整份候选未通过旧记录保护校验时，将本轮候选标为失败并保留审计内容，重试重新提取，避免反复复用同一份不完整结果。
- 一个报告只允许一个未结束批次；数据库唯一索引和触发器阻止并行页面修改、成员变更及普通处理任务。整份报告可以直接移入回收站，在同一事务中先停止补页和识别任务；恢复报告也不会重新接受旧任务的迟到结果。事务内再次校验版本，AI 发布前校验整份输入指纹，旧租约/旧回调不能覆盖新状态。
- 草稿请求、文件和预览同时绑定账号、报告和批次。管理权限在外部 OCR/AI 调用前后及发布前再次验证。管理员没有隐式成员权限；撤销原账号授权后停止工作，其他管理者后续操作会释放失效草稿锁。
- 发布后详情返回 `pageAppend.originalRevision` 和 `recognizedRevision`，未完成新识别时提示原件与结果不同步。只读者不会获取未发布草稿页。

## 文件与恢复

文件写入 `reports/<报告 ID 摘要>/appends/<随机批次 ID>/`，预览写入 thumbnails。它们从开始即处于已有完整备份/存储迁移覆盖范围，不受 upload-staging 七天清理影响。文件清理把未结束批次作为有效引用；放弃、全部重复或完成后的未引用文件由已有孤儿清理回收。NAS 复制复用原上传的格式检查、大小限制、受限读取和安全复制函数，不修改源文件。

备份恢复保存草稿、原操作者、任务检查点及文件；权限仍遵循现有恢复确认逻辑，不能用备份替原操作者增加权限。跨实例身份待确认时不能继续后台发布。

手动永久删除报告时，连同已放弃批次的文件和预览立即进入现有删除流程，仍被其他正式页面引用的源文件不会被误删。

## 安全边界与保守行为

近似重复只比较当前报告和当前批次，并且只是提示。不同 OCR 版式、缺少可靠身份标签的文件仍需使用者核对。旧记录保留校验偏保守：即使是 AI 合理改写，改变已有临床事实或指标也可能被拒绝；可以保留原件/OCR后人工校对，避免自动丢失历史结果。

原件、OCR、AI 响应、姓名与指标内容不写入批次公开错误或日志。真实 OCR 引擎、外部 AI 服务、fnOS 文件授权及真实设备交互需在部署环境验收，自动化使用合成数据和可控服务替身。

待核对提示直接读取已有候选及单元审计，不新增任务状态或数据库字段；完成后释放补页锁，疑点可通过原件和现有指标核对入口处理。单独上传的识别策略不变。
