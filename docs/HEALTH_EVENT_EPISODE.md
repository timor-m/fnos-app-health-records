# 五类健康记录与健康历程

## 用户看到的分类

导航顺序为报告、症状、用药、接种、影像；影像作为暂未开放入口置后，概览和筛选均禁用，不提供原始影像上传或阅片。上传页与新增菜单单列禁用影像入口，图片/PDF 检查报告仍可走资料上传，既有报告可通过全部记录及原详情链接查看。数据分类与既有归档不变。

记录页统一展示五类卡片。顶部筛选可继续细分来源或操作状态，不增加同义卡片类型。

| 分类 | 范围与边界 |
| --- | --- |
| 报告 | 体检、检验、病理、功能检查、门诊病历、住院资料及其他医疗资料；费用凭证作为报告细分，不另建费用模块 |
| 影像 | 影像检查的报告、图片和 PDF；当前不包含 DICOM 阅片能力 |
| 症状 | 实际不适及其程度、变化和相关测量；不承接无症状的日常监测 |
| 用药 | 对外仅区分用药单和用药记录；开始、调整、停药及独立服用统一归入用药记录，按次服用在详情中作为选填补充 |
| 接种 | 统一展示接种信息，上传原件作为附件；支持手动填写、剂次与下一剂提醒 |

日常血压、血糖、体重等监测为独立“监测”分类：从新增菜单「记录测量」录入，一会话可含多项，与报告指标共用趋势轴并标注自测/设备来源；不塞进症状，也不伪造报告。设备接入复用同一 ingest 接口（`channel=device`）。

健康历程串联同一阶段的症状、就诊、治疗、用药、监测和复查，是可选关联，不是第七类卡片。同一次的多份资料由内部分组保存，不提供独立的诊疗经过业务入口。

## 主要流程

- 上传图片、PDF 或从 NAS 导入后，原件先保存并自动分类。用户可以纠正类型，将明确属于同一次的资料放在一起，或直接分别保存；不需要先选择体检、就诊、检查事件类型。上传页默认不查询或展示历史待整理资料，只在本次上传成功后展示对应资料；本次进度在前、资料结果在后，分类和合并通过“调整资料”按需打开，查看记录无需先整理。直传、分片和 NAS 导入均以本批回执限定资料范围，失败重试保留已成功部分；开始新一批、继续上传或离开已完成的页面后清理旧结果，原件仍在记录页。超过 100 份的本次结果仅在当前回执内分页读取，调整按每批最多 100 份进行，已调整资料不会重复提交。
- 单份资料直接保存，不制造空事件；明确确认的多份资料才建立内部分组。同组的报告和影像仍分别以各自分类呈现，已关联的报告不会从记录列表消失。
- 症状入口直接填写名称、发生时间及补充情况，可选关联已有记录；新增症状、症状编辑与变化记录的程度共用 0～10 数字标签，12px 字号、4px 间距，支持键盘操作；标签随分值从青绿经琥珀逐步过渡至红色，适配浅色与深色主题，选中项使用实色背景、内描边和加粗数字辅助识别，颜色仅表示程度高低，不表示时间变化或诊断阈值；已选择分值时在标题右侧提供“清除”，未填写时隐藏该操作；清除后取消高亮并将键盘焦点移至数字区，不默认选中 0 分，保留 0 分与未填写的区别，不预选、推断或改写已有程度。用户可见的健康历程仅在至少两条记录建立关联后形成。症状的内部历史容器只承载原始条目及更正记录，不作为用户可见过程，起始和变化日期不再受内部容器起止范围限制；仅校验症状自身的发生顺序及非未来日期。记录卡片和详情对应实际症状条目。详情顶部集中状态、编辑与回收站，下方按症状信息、补充描述、变化记录及健康历程分区，统一 16px 加粗标题、细分隔线与紧凑间距；症状信息承载日期、最近程度与测量、部位及频率，“新增变化”与“症状信息”标题同行靠右对齐；补充描述承载描述、诱因、缓解因素及伴随症状，字段按标题在上、正文在下排列，长文左对齐并换行，无内容时隐藏整个分区；PC 的基础字段按两列排列，完整描述独占一行，较短的诱因、缓解因素和伴随症状按三列排列，触屏保持单列；独立详情页和弹窗均由标题栏承载症状名称，正文不重复。单条详情与用药共用状态标签、紧凑操作按钮及历史折叠样式，字段沿用档案详情的标签和值对齐行；状态、编辑与回收站入口合并到顶部同一工具栏，状态靠左，编辑及回收站靠右；“新增变化”位于症状信息标题行右侧，开始时间、最近程度及其实际记录时间独立展示，零分保留，缺少时间不补造；已有部位、频率和诱因等直接展示。变化历史按实际时间倒序；单条详情默认展开变化记录，可手动收起且刷新保留当前开合状态，无记录时隐藏整个历史区，先展示最近三条（包括明确标注的已撤销项），可继续展开全部，详情时间保留年份，过程内跟踪列表仍直接展示最近三条，保留更正与撤销语义；单次变化的纠错和撤销收进更多菜单，编辑保留次要入口，整条症状沿用统一详情工具栏的移入回收站操作，入口采用纯图标，保留悬停提示和无障碍名称，触屏图标占位 28px、点击范围 44px。详情仅展示所属健康历程摘要与查看入口，完整记录及成员管理集中到历程详情；触屏在历程内以独立弹窗查看原始记录，关闭后恢复原位置。症状及关联刷新保留已展示内容，失败可重试，不因一次保存清空历史展开。
- 随手上传的用药单自动归入用药；点击用药单直接打开报告详情，在同一详情查看单据与识别药品、确认实际使用，不再先经过用药汇总再打开原件详情，弹窗正文不重复展示单据标题。用药单详情及字段校对隐藏不适用的部位项，避免将“用药”分类兜底值标为部位；已有药品、用法和机构信息保持展示，校对其他字段时保留原部位数据。新增用药支持报告带入、手动添加及单次实际服药三条路径；报告药品的“确认实际使用”也复用独立确认弹窗，取消返回原报告，成功后打开已保存的用药。新增用药弹窗在 PC 与触屏均固定紧凑的取消、提交操作，展开补充信息时只滚动正文；保存失败保留草稿，后台刷新不卸载首次新增的表单。同一草稿重试沿用提交凭据，阻止保存中重复提交。单次服药选择已有用药时展示当前状态；切换药品清空上一次实际用量和单位，保留所选健康历程。新增服药与编辑原记录分别使用“新增服药记录”和“保存修改”。用量单位在用药方案、实际服药、历程快捷记录和报告药品校对中共用紧凑标签选择，常用的片、粒、袋、mL、mg、g 直接点选，再点可清空；“其他”展开其余单位及自定义输入，不预选或换算单位，保留报告单位原文及大小写。标签文字为 12px、间距 4px。处方事实、用户确认使用、实际服药保持独立；识别出药品不会自动表示正在服用。同一单据集中展示识别药品，确认后的用药保留来源关联，避免重复铺卡片。用药细分筛选仅保留用药单（`prescription`）和用药记录（`record`）；后者同时包含已确认用药与独立服用补充，已关联服用不重复铺卡。不保留本轮中途的 `course/intake` 筛选值转换；实际记录仍以现行类型打开详情。
- 接种统一为一种记录，不再把“接种凭证”和“已接种”设为细分类型。上传后直接展示接种详情和原件附件，识别完成但信息尚未保存时显示“待完善”，上传或识别中的状态仍按实际进度显示；识别结果不自动视为已接种。通过“完善接种”复用接种编辑表单，保存后原地显示接种详情，不经过凭证列表、已记录确认和返回凭证等中间层。已有来源链接直接打开对应详情，同份原件包含多条接种时在详情内切换。手动创建及编辑接种均可在“原件附件”中直接上传图片、PDF，支持多文件、移除待上传文件和上传进度；单文件上限 40 MB，本次附件总大小上限 200 MB。文件在保存时与接种一起落库，取消填写不上传；校验或保存失败时回滚原件、接种及提醒，并清理新文件，重试沿用请求编号避免重复生成。已保存的手动接种在详情的“原件附件”区直接显示“上传附件”，选择文件后立即上传，无需进入编辑；上传仅提交记录身份与版本，不修改日期、剂次或提醒。已有原件时，同一区域保留“上传附件”入口，复用原件补页流程继续添加。失败保留所选文件，可直接重试；上传期间保护关闭、编辑与删除等操作，防止未完成时切走或覆盖记录。标题同行的“关联原件”仍可选择已有资料、带入识别信息并保留手动修改；直接上传附件保留手填接种字段，也可不关联附件。接种详情直接复用报告的原件查看、下载和补页区，不再另开凭证详情，也不重复展示报告头部、处理日志和删除按钮。旧 `vaccination/administered` 筛选链接归入统一接种分类，既有详情链接和数据关联继续可用。原件附件的上传按钮与标题同行，说明文字另起一行，PC 与触屏保持一致。
- 已接种卡片的剂次与状态同处顶部标签，疫苗名称独占标题行，机构和备注合并为单行摘要。下一剂日期生成提醒，从提醒登记后一剂后原提醒完成。接种沿用统一“移入回收站”流程，新移入记录保留 30 天，可恢复或永久删除；回收站中的接种仍保留原件关联，原件不重新出现在列表成为待完善接种，恢复后直接查看同一附件。永久删除最后一条引用接种原件的接种时，将闲置原件移入报告回收站另保留 30 天，避免原件重新变成接种卡片；仍被其他记录或过程使用的原件及其他类别的报告保持原状。移入后一剂时，已完成的前次提醒恢复为待接种，当前未完成的下一剂提醒取消；恢复按保存的提醒状态还原，用户此前取消的提醒保持取消。恢复元数据缺失时保留现有提醒状态并提示核对；已有后一剂时先处理后一剂，恢复时先恢复前一剂。日期或剂次有误使用“编辑接种”，仅取消提醒时使用“取消提醒”。本次仅合并展示和交互，沿用现有接种、临床事实和原件存储，不新增迁移，schema 保持 v19。
- 成员管理仅展示成员资料、本人关联和共享权限，不嵌入用药汇总或加载服药历史。用药统一通过“记录 → 用药”查看，成员资料里的“长期用药”仍作为选填健康背景供就诊摘要使用，不代替实际用药记录。

## 记录关联形成健康历程

用户从任意记录选择相关记录，一次保存即可建立直接关联，无需先建过程、选择所属过程、填写过程标题或核对预览。两条记录关联形成一份过程；第三条关联其中任意一条即加入；连接两个已有过程时合并完整范围。连接顺序不决定展示顺序。所有参与记录的详情均有可直接打开的健康历程入口，过程页通过“补充记录”关联已有记录或新增资料、症状、用药和接种；该菜单独立浮层展示，依据按钮与可视区域自动上下展开并约束左右边界，空间不足时菜单内部滚动，打开时保留页面位置，屏幕或可视区域变化后重新定位；已有历程的补充入口携带 `processId`，上传、新增症状、用药与接种保存时加入该历程，不再以某条记录作为公开关联目标；历程详情选择已有记录通过 `POST /api/health-processes/:id/records` 加入，并校验历程归属、版本和请求编号。

过程由同一成员的明确记录关联组成，单条未关联记录独立保存，不占概览过程模块。来源用药单、接种凭证、所属用药及前后剂次关系单独保留，不隐式生成过程边或合并其他健康问题。症状的归属与历史修订不因过程连接、合并或拆分而移动，接种剂次与提醒、已确认用药状态同样不受影响。

各类记录详情点击“关联记录”打开独立弹窗，沿用原弹窗外壳，触屏保留拖拽条；按类型筛选、名称或临床日期搜索，支持分页和跨筛选保留勾选，每次 1～20 条。列表展示标题、类型、日期和机构，排除当前记录及已直接关联记录。标题、筛选区和取消/确定按钮保持可达，列表独立滚动；点击“确定”直接保存入库，成功后关闭关联弹窗并刷新原详情，不再在正文展开编辑或增加确认步骤。失败保留选择和搜索，可原地重试；关闭返回原详情的滚动及焦点，成员切换和权限收回关闭弹窗，过期保存响应不更新新上下文。服务端校验成员与管理权限，拒绝自身和重复关联。写入事务保证多条关联全部成功或全部回滚，稳定请求编号支持丢失响应重试。取消和离开保护未保存选择。直接联系与经其他记录传递的联系明确区分；解除一条边后重新计算过程，仍然连通的记录保留在同一过程，分离成两组时各自形成过程，孤立条目退回独立记录，不删除原始数据。

新增症状、用药和接种表单共用“关联记录”入口及同一独立选择弹窗，不再在表单中展开记录列表。按类型、名称和日期筛选，勾选后点击“确定”回到表单并显示已选数量；再次调整保留已确认的勾选，可清除全部选择。新增记录尚无实体标识，选择弹窗只回填本地表单，保存表单时才将记录及关联一起入库，不提前写入或生成空历程。取消选择不覆盖上次确认的内容，取消新增不产生关联；改变勾选后关闭沿用未保存保护。切换成员、失去管理权限或离开缓存表单时关闭选择弹窗，恢复父弹窗和滚动锁。由历程发起的新增继续显示“保存后加入当前健康历程”，保留既有上下文。

健康历程“补充记录 → 关联已有记录”同样打开独立关联弹窗，排除当前历程已有记录，确认后沿用历程记录接口及指纹、稳定重试键保存；失败在弹窗内保留勾选并允许重试，成功刷新原时间轴，取消、失去权限或离开页面时恢复原页面和焦点。本轮尚未发布，早期诊疗经过详情页、事件关联入口与对应公开事件接口已撤除，不保留旧业务兼容入口；提醒和上传仅携带实际记录、历程与提醒上下文。报告同次资料分组和症状变化仍使用各自内部存储，不另造记录类型。关联列表显示“已有关联历程”，按记录身份归一化报告和用药单引用，排除已有记录并识别已选项。更换搜索词立即废弃旧游标和结果，避免混入旧分页。

移入回收站时保留关联边，但过程只呈现当前有效记录并重新计算可见连通范围；恢复时按保留的边重连；永久删除清理相应边和节点。过程信息不替代记录的权限及生命周期。

## 时间轴、摘要与概览

历程详情及快速记录、变化明细、复查与待办的首次加载统一复用居中转圈与文字提示；已有内容刷新时保持展示。

首次进入同时请求历程主体与 `GET /api/health-processes/:id/activity`，主体返回即可展示摘要及时间轴，不等待辅助模块；仅需自动整理时安排下一轮任务，不在读取已整理详情时重复准备 AI 任务。activity 在单次请求内复用已校验的历程与基础记录快照，返回快速记录、首屏变化明细与当前历程提醒；各模块错误独立返回通用提示，可通过原模块入口单独重试。前端校验成员、历程及记录指纹，若两次并行读取之间发生记录变更，模块改为重新读取，不复用过期结果。不使用跨请求或跨成员的健康数据缓存。

快速记录使用 `care?view=quick`，仅准备症状、用药快捷项与体温统计；点击“给医生看”才通过完整 care 接口准备按内容和按天的就诊摘要，弹窗立即打开并显示居中加载，失败可重试。报告摘要直接读取主诉、结论、印象、建议及必要结构化章节，不再读取指标判读、页面和 OCR 证据等完整报告详情；背景读取复用当前已授权历程。关闭后可复用当前摘要，记录或历程信息变化、离开返回后重新核对。

复查与待办通过 `GET /api/health-processes/:id/followups` 按当前有效记录的来源关系筛选，保留明确依据优先于旧报告来源的规则；通用提醒列表在单次请求内按成员批量计算归属，避免每条提醒重复遍历历程。变化明细独立筛选与翻页只读取症状和实际服药来源，不读取报告诊断、处方及操作信息，保留原有计数、实际时间排序、分页游标及修订校验。已加载的空待办刷新时也保留空态。本次不新增数据库结构、版本或迁移。


健康历程时间轴右上提供紧凑的“流程｜时间”分段切换，两种模式都保持倒序，默认使用流程，并在本设备记住上次选择（仅保存显示模式，存储不可用时仍可切换）。流程模式按既定阶段顺序倒序分组，仅显示有记录的阶段；即其他记录、复查、接种、用药、治疗、检查、就诊、症状。组内子项按实际发生时间倒序，未知日期置于所属阶段末尾，阶段名称只在组标题展示。时间模式将全部记录按实际发生时间统一倒序，按本地年月分段，未知日期统一置后，阶段信息保留在卡片中。两种模式都不借用上传时间、最近变化时间或历程时间补造日期，同一时间按记录引用稳定排序。切换仅在当前已加载数据上重排，不发起额外请求或 AI 调用；已滚入时间轴中部时保留首条可见记录的位置，在起始处切换保持控件可见。查看者也可切换模式。此项仅调整详情页展示，不改写原记录、阶段、接口返回顺序或 AI 缓存。默认阶段来自记录类型，用户可在过程内调整，调整阶段不修改报告分类或原始事实。复查不能仅凭日期较晚自动判断。

复查与待办独立于已发生的阶段时间轴，提醒通过 `health_record_reminders` 关联具体来源记录，过程合并或拆分后跟随来源；上传实际复查资料时直接关联来源、归入复查阶段并完成提醒，同一批多份资料可共同加入。计划本身不计记录数量，也不参与实际覆盖时段。过程页预览待处理计划，并通过折叠的“已完成”回看实际复查资料或手工完成状态。记录复查支持上传新资料或单选一份已有报告；已有报告关联来源、归入复查阶段并完成提醒，不重复创建报告。跨历程选择会提示合并，保存后进入实际保留的历程；延期、手工完成和忽略收进“更多”。无计划时隐藏整个复查模块，从“补充记录 → 添加提醒”仍可新建。

覆盖时段由有效记录的可靠日期及症状变化、用药变化的实际日期计算，未知时间保持未知，不拿上传时间兜底；最近资料日期不表示康复或过程结束。记录列表仍按原五类展示，不增加健康历程卡片类别。

独立 AI 任务 `health_process_summary` 复用已有文本模型与场景绑定。过程可先直接使用，模型只整理标题、摘要、带原始记录来源的重点和阶段建议，不创建、删除或合并关联，不写回诊断、日期或原始记录。输出校验来源范围、长度与阶段枚举；失败只显示通用错误，不持久化上游健康原文。源记录版本或关联范围改变时，旧摘要不再展示；模型返回后重新核对指纹，过期结果丢弃。手工标题、摘要和阶段优先保留，AI 不覆盖。 点击“AI 整理”立即显示转圈、执行状态并阻止重复提交，完成后提示结果，失败保留原历程并可重试。手动及自动整理统一进入 AI 审计，执行中可查看状态，结束记录实际模型、Token、耗时及安全原因码；源数据变化时记录“结果未应用”。审计复用已有 `audit_logs`，仅存执行元信息与对象标识，不保存成员名称、报告或历程标题、健康原文、模型原文及凭据；列表标题按当前权限读取历程，用户操作日志清理保留 AI 审计记录。此前未记录的调用不补造历史日志和用量。本次无结构变化，schema 保持 v19。

模型输入由程序直接拼接为按记录组织的紧凑概览文本，无需额外 AI 预摘要。保留每条记录的来源引用、类型、实际日期、标题及当前阶段，正文优先选择诊断、报告结论与印象、少量结论类章节、原报告建议和用药概要；去掉空值和重复内容，不发送完整检查表或全量指标。仅当整个过程都缺少报告结论、症状描述或变化、用药概要等概述内容时，才以异常指标兜底：每份报告最多补充 5 项有原报告异常标记的指标，保留原值、单位及原始标记，不以参考范围推导的异常代替原报告判断。任一关联记录已有概述，就不再附带其他报告的指标；标题、日期、机构及症状默认状态本身不算概述。症状和用药各取最近 3 条有效变化，保留当前状态及零分；服用补充只汇总有效次数。省略内容不表示正常、未发生或不存在。

资料正文最多 12,000 字符，单条记录正文最多 1,800 字符，并按记录数量分配可用篇幅；所有来源引用和实际日期完整保留，超长正文按完整信息行节选。若仅记录头部就超出总预算，停止本次整理而不发送无界请求，原始记录和关联仍可使用。请求输出上限为 1,600 tokens，提示模型返回简短标题、200 字内摘要及最多 5 条带来源的重点；阶段建议只列需要调整的记录。字符预算不等于模型计费 token，用量仍以实际模型返回为准。

概览首次加载及切换成员时，骨架屏沿用五类统计、资料处理、历程摘要和记录卡片的布局及触屏尺寸；占位不显示虚构数量或可点击入口，减少动态效果设置下停止动画。刷新已有数据时继续展示当前内容，不切回骨架屏；初次读取失败后显示错误与重试。概览增加紧凑的健康历程模块，最多展示最近实际记录日期靠前的三份过程，包括标题、覆盖时段、记录数量和摘要，点击进入同一过程页；无过程时隐藏。概览历程卡片右侧使用垂直居中的紧凑箭头，整张卡片保持可点击，并保留“查看历程”的可访问名称。模型刷新不会将过程排到最前。未配置或未启用 AI 不影响关联、阶段视图、记录查看或手动编辑。

历程标题围绕资料明确支持的具体健康事项命名，优先表达症状、诊断、检查目标、治疗事项或疫苗名称，仅在有依据时补充就诊、治疗、接种或随访目的。单条诊断不能扩大为全部记录的共同疾病；缺少共同主线时并列概括具体事项，不强行构造同一诊疗过程。禁止只拼接记录类型或添加“健康记录概览”等前缀。新生成及旧缓存标题共用清理规则，去除套话后仍有具体事项时保留；仅有类型、空泛概括、超长或带省略号的截断标题时，明确显示“待命名健康历程”，不再拼接或截断原报告名称。AI 标题使用完整自然的事项短语，不复制医院、文件名或完整项目清单，最多 30 字；仅有处方或治疗医嘱时保留“处方／医嘱”限定，不暗示已经执行治疗或实际用药，也不根据药品组合推断治疗方式；仅有症状自述时保留症状或跟踪语义，不补造已经完成的就诊评估；缺少具体事项依据可返回 null，保留可用摘要与原始记录，完成提示说明标题尚未明确并可手动命名。手动标题原样优先保留。清理旧标题只影响读取结果，不改写缓存、原记录或关联，也不触发额外 AI 调用；用户再次点击“AI 整理”时按新规则重新生成具体事项标题。

## 用药来源与历程继承

来源用药单、所属用药与所属健康历程分别保存。新增确认用药、单次服药以及历程内快捷服药均遵循同一规则：

- 从用药单带入时保存具体药品事实标识、当前可访问的来源报告及当时的处方快照；从已有用药记录服药时保留所属用药并复制来源快照。报告重新识别、合并或不可用，不改写已记录的处方快照。
- 来源用药或来源报告已在健康历程中时，新记录自动加入同一历程；来源尚未加入历程时仅保留来源，不为了来源关系单独建立历程。新记录的加入不追溯改写旧来源的所属历程。
- 手动选择的历程、相关记录与来源所属历程必须一致；冲突返回 409，记录、修订、关联及重试回执一并回滚，不静默合并。明确关联记录的独立管理入口仍可由用户主动连接历程。
- 快捷重复服药沿用具体来源记录的快照；只有来源药品标识及实际规格等均一致时，才带入上次实际用量作为待确认值。不能根据同名药品推断来源，处方剂量不直接当作已经服用的量，保存仍要求本次实际时间及用量。
- 详情分别提供来源用药单、所属用药和健康历程入口。旧服药已有所属用药时，可读取其明确保存的来源；旧独立服药缺少来源标识时不猜测补填，已有历程关联保持原样。
- 报告归属调整时清除跨成员的来源入口并保留原始快照；报告合并指向保留的报告，永久删除由外键清空来源入口。导出及备份保留服药快照，恢复前校验来源的成员归属。

服药来源字段使用可空的增量草案，沿用 schema v19；旧库补齐前备份，失败停止启动，重复启动不覆盖已有记录。不递增应用或数据库版本，不修改已发布迁移。

## 数据及接口

用户操作日志覆盖症状登记与变化、用药调整和服药补充、接种、回收站及历程关联，同次资料整理按资料分组展示，不把症状内部容器记录为新增健康历程。操作名称、对象类别及关联数量在读取时转换为可读文字；新增对象名称从当前有权限的原记录读取，不将成员、症状、药品或报告名称复制进持久化日志。已删除、已移交或失去访问权限的对象显示明确占位，既有日志无需改写即可展示。AI 整理仍归入独立 AI 审计。回归检查直接扫描当前审计写入点，并覆盖用药及回收站的动态操作，新增操作或对象类型缺少映射时测试失败。

共享契约为 `packages/shared/health-categories.ts`，公共 `category` 只允许 `report / imaging / symptom / monitoring / medication / vaccination`。内部 `kind` 用于定位详情，允许 `report / symptom / medication_document / medication / intake / vaccination / measurement`；它不是卡片分类。

## 交互约束

上传分组草稿及同内容重试键在当前浏览器会话保留，后台识别不会覆盖手动分组；纠正分类只更新所选字段，保留标题、日期和其他元信息。用药首页合并同一来源；“用药记录”细分统一展示已确认用药和独立服用补充，关联服用留在对应详情，不额外铺卡。

记录页保留搜索、下拉刷新和滚动加载。搜索获得或失去焦点不重新加载未变化的查询，刷新时保留已有卡片；失败可重试。PC 详情打开二级页，触屏在原列表打开详情弹窗并保留筛选及滚动位置，原生新标签及快捷键行为保留。

列表、详情、来源选择和保存均校验当前成员、路由和请求次序；切换成员或离开页面后不混入旧请求。查看者只读。上传来源上下文在直传、分片和 NAS 导入中一致传递；多候选由用户选择，不能静默跨成员或丢弃上下文。

新增与整理使用稳定 `requestKey`，同内容重试读取已保存实体，内容改变必须换键；编辑、移入回收站以版本号防止覆盖。已确认用药、实际服药和接种保留当时事实，不因重新识别报告而改写。

## 概览

概览的分类数量与记录列表的合并展示一致，不用原件份数替代记录条数；仅有手动症状、用药或接种时也正常展示计数及当前关注，不显示最近上传列表。`GET /api/overview?memberId` 返回五类计数、最近上传资料、待处理资料、提醒总数及预览、当前关注的症状和用药。最近上传（接口字段 `recentRecords`，最多 5 份）及资料处理（最多 2 份）均按原件上传时间倒序，同一时间按 ID 稳定排序，资料处理不再按状态优先排序；合并或已确认的资料按原件逐份展示，排除已删除资料及其他成员。两处卡片显示上传时间与报告日期：报告日期与记录列表共用卡片组件，保持右上角位置及月日、可用时分格式，不显示“报告日期：”前缀，完整日期保留在无障碍说明中；上传时间单独放在卡片底部；上传时间按查看设备的本地时区显示，今天、昨天使用相对日期，其余显示完整日期和时分；接口以带 UTC 时区的时间戳返回上传时间。报告日期未识别时标注待确认；手动记录、重新解析或修改报告日期不改变上传顺序。记录页仍按报告或健康事件日期展示时间轴。

待处理资料按原件份数分别统计待确认、处理中（包含上传中及排队）和识别失败，显示最近上传的待处理资料；触屏处理统计使用紧凑的两行布局，点击区域至少 44px 高；已确认接种或用药中的来源资料仍纳入处理统计。提醒总数独立计算，不受预览条数限制，下一剂接种提醒可直接进入填写。当前关注只计实际持续跟踪的症状和已确认正在使用的用药过程，不由处方推断正在服药。资料处理在三类处理数量均为零时整块隐藏；当前关注在症状和用药数量均为零时整块隐藏，仅有历史记录不会保留空模块，单项关注不展示另一类的零值入口。提醒独立展示，空模块隐藏后不留布局占位。

概览顶栏副标题只显示当前成员的记录总数，页面内容直接从五类统计开始，不重复展示标题、成员和总数；切换成员、离开页面或加载失败时不沿用其他成员的数量，下拉刷新继续保留。

PC 对单张关注卡片和单条提醒使用完整可用宽度；触屏操作保持至少 44px 点击高度，窄屏分类保持五列，五类记录在概览、分类筛选、卡片、详情标题及新增入口中共用轻立体透明图片图标，症状跟踪、用药详情和关联资料等位置同步使用；图片不额外叠加背景框，并保留类型名称和必要的替代文字。概览中，PC 图标在左、名称和数量在右，触屏使用“图标、名称、数量各占一行”的居中三行布局，各自指定网格区域，避免多位数量或按钮状态影响对齐；常规高度为 70px，较长数量缩小字号并保留完整值，并对长标题及成员名称自动换行；记录卡片的资料类型与分类、状态同处顶行，超长类型省略显示并保留右侧日期时间；下方机构摘要仅展示一行，超出宽度显示省略号，没有机构时不占行。

分类、资料处理和关注入口通过 `category/subtype/status` 跳转记录页，筛选可清除，刷新和返回时保留查询条件。概览使用相同的记录卡片，日期统一显示为 `MM-DD`（如 `09-20`），有时间时显示 24 小时制的 `HH:mm`（如 `20:09`），不补造缺失时间，日期时间整体右对齐；记录卡片移除右侧箭头及其网格列占位，整张卡片仍可点击。触屏保留右下角 48px 浅色类型图标作为背景，不占正文列；PC 保留左侧 40px 图标及 10px 图文间距；PC 打开详情页并可返回概览，触屏原地弹窗，浏览器返回关闭，成员切换及离开页面后忽略旧请求并清除详情。

健康历程新增结构维护在未编号草案 `health-record-process-draft.ts` 中；应用和 schema 编号不递增。

## 数据完整性与验证

报告改归属时解除原成员的诊疗经过和直接过程关联，已确认用药与接种留在原成员，保留事实快照并解除可变来源引用。重复报告合并转移有效来源与过程关联；成员合并在事务中迁移相关记录，不扩大权限。解除关联后重算过程，原始资料、用药和接种独立保留。

全量备份保留新增业务结构及关联；成员导出包含实际接种和资料过程联系，不导出重试密钥。缺少整组新增结构的正式旧备份可先补齐；部分缺表、跨成员关联及不一致历史拒绝恢复。

接种回收站在既有接种表增加可空的 `purge_after` 与 `trash_state_json`，分别保存保留期限与移入前提醒状态；旧库缺列时先备份再幂等补齐，不覆盖既有接种，不修改既有字段语义。元数据缺失时不推断到期删除、不猜测提醒前态；操作日志清理不会影响恢复或保留期限。

**0.3.2 已发布**，schema 保持 v19。当前开发为 **0.3.3 Unreleased**，不发版、不改已发布迁移，也不另增数据库版本。临时安装过的 0.3.0、此前未发布的 0.3.1 与已发布的 0.3.2 区分。新增独立结构维护在未编号草案中；新库初始化，已有库检测缺失后先备份、再幂等补齐，失败停止启动。保留已落库开发数据，不降号、不清库；不为本轮未发布的旧列表或事件抽象保留接口适配层。正式发布前仍需对照最近发布基线判断结构兼容性，不能仅因新增表就递增 schema。

回归覆盖分类、关联资料可见性、影像分离、真实症状、用药快照与实服、接种来源和剂次提醒、成员权限、归属调整、合并、导出、备份恢复，以及列表分页、重试、成员切换和详情路由。手工验收使用独立临时库和合成资料；OCR/AI 外部识别及 fnOS、Docker 实机部署另行验证。

### 接种录入与详情交互

新增只要求疫苗名称和接种日期，剂次、机构可选；新增接种页的凭证入口与标题同行靠右，不占表单行，触屏标题栏为 32px 高，标题字号 16px、图标 22px，并收紧标题与首个字段间的留白；返回及凭证按钮保留至少 44px 点击范围。PC 点击即展开列表，触屏复用底部选择器；带入结果和多条接种信息的选择就近展示，备注及补充字段按需展开，日期提供“今天”快捷操作。凭证带入保留手动输入，多条识别结果需明确选择来源；凭证只保留一个“核对并记录”入口，完成后显示已记录和查看入口，编辑结果同步回凭证列表。

详情优先展示日期、剂次和机构，隐藏空字段与触屏重复标题。下一剂日期在详情原位调整，取消与恢复只改变提醒状态；修改疫苗名称不会恢复已取消提醒，已登记后一剂时展示查看入口并保护剂次联系。保存按钮固定可见、内容单独滚动；接种及提醒表单统一使用成组的取消与保存按钮，PC 靠右、40px 高，触屏使用靠右成组的 32px 按钮并扩展至 44px 点击高度，保存栏整体常规高度为 40px，上下留白各 4px；录入页由顶栏、可滚动表单和底部导航共同分配视口高度，移除内容区重复的底部留白，新增页不重复预留底部导航已承担的安全区，弹窗保留系统安全区，取消为次要操作、保存为主操作；取消、关闭、路由返回及浏览器离开统一保护未保存内容，返回保留来源及筛选。

### 记录页样式约定

用药新增的报告带入、手动添加和单次服药分别打开独立弹窗，沿用共享外壳及对应操作标题。同一时刻只显示当前弹窗，上一层保留状态；取消或关闭返回上一步，报告搜索保持不变，填写后关闭需确认未保存内容。从记录列表新增并保存后关闭新增流程，刷新原筛选列表。已确认处方的“再次开始用药”与“查看已确认用药”直接并列展示，移除折叠入口及重复说明；再次开始用药仍需在表单内确认确实新建一段用药。

单条用药与单次服药详情沿用档案的字段行、状态标签、紧凑操作区；状态和顶部右侧回收站入口合并到同一工具栏。用药详情逐项展示规格、剂型、每次用量、频次、途径和起止日期，说明及来源按实际内容展示；处方确认快照、使用历史默认收起，有服用补充时再展示对应列表，已撤销补充按需显示。单次服药仅展示那次保存的规格、服用量、时间和备注，不混入当前方案的用法；编辑时隐藏详情内容，取消后返回详情。详情弹窗标题使用药名，正文不再重复汇总标题、数量和药名；报告选择流程保持列表布局。

触屏两级筛选作为整体吸顶，位于标题搜索栏下方，吸顶偏移共用标题栏高度变量（含系统顶部安全区）；宽屏触控布局没有移动顶栏时偏移为零。筛选区上方留白减少 8px，背景铺满屏宽并遮住下方滚动内容，底部不添加分隔线。用户主动切换分类、细分类型或清除筛选时，若已滚过列表开头则回到首条结果，保留筛选横向位置；路由恢复及详情返回不主动重置滚动。两级筛选条只沿水平方向滚动，禁止内部纵向溢出，并通过 `data-pull-refresh-ignore` 排除下拉刷新手势。共享下拉刷新先锁定滑动方向，横滑、向上滑动、多指操作及系统取消手势均不触发刷新；列表区域向下拖动仍可正常刷新。


当前报告、影像、症状、用药与接种共用主题及紧凑卡片；类型、状态、日期置顶，数量与关联信息置底。分类图标按输入方式区分：PC 使用左上角 40px 完整图标，以独立网格列展示；小屏（≤760px）或触屏（pointer: coarse）保留右下角 48px、20% 不透明度的装饰背景，右侧及底部外移 6px 以抵消图片透明留白，并沿卡片圆角裁切，不占网格列。图标均不响应指针或参与可访问名称，顶部保留类型文字，正文与底部信息完整展示。状态标签复用主题色：已归档、已接种、正在使用及已缓解为淡绿，待确认为琥珀色，上传、排队及处理中为蓝色，识别失败为红色，未知、暂停及停用为灰色；类别颜色独立保留。主筛选桌面视觉高度 32px，触屏主筛选 28px、细分筛选 26px，两条按钮之间留白 4px，分别横向滚动；触屏滚动容器延伸至页面两侧边缘，选项起止留白与卡片对齐，横滑不在页面内边距处裁剪；状态提示并入细分筛选，任意分类、细分类型或状态筛选生效时，在主筛选右侧显示清除操作，移除硬分隔线，按钮底色向左右两侧渐隐，横滑区域右端同步柔化裁切边缘；文字保持完整不透明，一次清空这些筛选并保留搜索关键词。详情内容的留白集中在全局 `record-dialog-content.css`，由显式的 `record-detail-inset` 容器或既有区块承担，避免嵌套重复缩进；独立详情页同样适用，PC 内容撑满可用列宽；详情初次加载在内容区居中。触屏弹窗标题由已校验归属的详情数据提供，展示记录名称与分类图标，正文中的报告标题隐藏，接种原件附件同样不重复标题；独立报告详情保留正文标题，用药单沿用页面标题承载名称。资料切换和名称编辑后同步更新；长标题复用原有标题组件左右往返滚动展示，保留完整可访问名称，并遵循系统减少动态效果设置。报告、影像、用药单、用药、单次服药和接种详情将类型及状态与回收站入口合并为同一工具栏，元信息靠左、操作靠右；接种详情将“编辑接种”置于顶部工具栏的删除图标左侧，正文不重复编辑入口；按钮沿用症状详情的 PC 32px、触屏 28px 视觉高度及 44px 触屏点击范围。接种详情直接展示原件附件，不重复报告头部及删除入口。查看权限下保留类型和状态；各类记录详情的回收站按钮统一采用纯图标，保留悬停提示、无障碍名称、确认流程和触屏点击范围。记录详情弹窗标题栏左侧留白为 8px，类型图标与标题间距为 2px，保留 26px 图标以扩展标题可用宽度。关闭按钮采用 28px 布局占位与 18px 图标，扩展至 44px 点击范围，减少标题右侧留白。资料切换使用独立按钮组，不复用表单提交按钮布局。接种字段与补充字段共享网格、输入控件及焦点样式。


### 记录页交互与数据流程复核

- 搜索词与分类、细分、状态共同保存在页面地址中；细分选项与服务端类型共用定义，废弃的用药细分归并为用药记录。详情返回及新增取消保留来源查询，切换查询时不携带旧游标。相同查询刷新会补取原先已加载的范围，完成后统一替换；失败保留已有卡片。
- 新增症状先填写名称、日期、部位和描述，关联记录与其他补充信息按需展开。症状起始和变化时间表示已发生事实，不允许未来日期；提醒日期仍可安排在未来。
- 症状新增、变化记录、用药编辑、接种、报告字段、指标、诊疗内容、结构化原文、形态发现、检查时间及补充记录共用未保存保护；健康历程和诊疗经过编辑也保护路由离开，并在相关数据重读时保留未保存字段。正在提交时阻止再次提交或离开；过期响应不关闭新打开的编辑器。
- 手动新增诊疗条目、原文区块及检查时间使用稳定重试标识；相同请求重试返回既有结果，内容不同、原条目已删除或报告成员已变化时拒绝复用。手动报告编辑共享既有 `source_version`，编辑器保留打开时的版本，并发变化时保留输入并提示重新核对。此项不改变 schema 编号。
- 列表日期搜索与相关记录显示遵循查看端时区；纯日期不补时间、不因时区偏移变更日期。分页绑定查看端时区，防止跨时区复用游标。
- 报告与症状表单沿用共享底部操作样式：PC 按钮 40px，触屏 32px 并扩展点击范围，避免保存栏过高挤压内容。

### 统一详情删除入口与回收站

用药单与报告共用 `ReportDetail` 的同一操作布局：顶部只展示类型、状态与回收站入口；确认归档、校对字段、查看 OCR 和 PDF 按权限与原件情况，统一展示在资料信息下方，不再为用药单单独挤入顶部工具栏。触屏下用药详情的“来源报告”“来源用药单”“所属用药”值左对齐并允许长名称换行，来源不可用时保留的快照说明同样换行。报告与用药单的信息操作按钮在触屏统一采用 32px 视觉高度和 44px 点击范围，窄屏按需换行。

报告、影像报告、用药单、接种凭证、症状、用药记录、独立服药及接种登记的详情共用顶部右侧“移入回收站”按钮，PC 与触屏文案、图标、位置和确认方式一致。待完善接种不用打开原件也能操作；切换同次资料时仅操作当前所选资料。症状过程中的次级列表同样复用该按钮，独立详情不重复展示移除菜单。查看者不显示入口，成员切换、未保存保护和过期响应检查仍适用。

回收站统一混排所有记录，恢复与永久删除使用各自版本号校验。症状移入后保留变化及关联；用药记录移入后隐藏其服药补充，恢复时返回原方案、调整历史及服药补充，不把移入操作记为停药。单次服药统一移入回收站，恢复后保留当时来源、实际用量和编辑历史。永久删除症状清理其变化及修订、保留健康历程与关联资料，不再运行早期症状回填；永久删除用药会清理其未单独移入回收站的服药补充，已单独移入的补充继续保留并可独立恢复。原件、其他记录和关联过程保留。

症状表补齐可空的保留期限，用药及服药表补齐可空的删除标记、保留期限。schema 保持 v19；新库直接初始化，旧库缺结构前先备份再幂等补齐，备份或补齐失败停止启动，保留原有行与字段。暂停、停药与症状变化撤销仍保留各自业务语义；服药移除统一使用回收站，不保留本轮中途的独立撤销 API、撤销状态或显示开关。

### 健康历程列表入口

界面统一使用“健康历程”，记录详情操作仍为“关联记录”，历程入口为“查看历程”。概览中的健康历程模块通过“查看全部历程”进入 `/health-processes`，不增加主导航或底部导航项。列表复用当前成员的历程摘要接口，按最近记录时间排序；与概览共同使用 `HealthProcessCard`，统一图标、标题、记录数、日期范围、两行摘要、分隔线及垂直居中的查看箭头，列表不再为每项叠加独立边框和不同间距；概览、列表及详情内的历程摘要按完整日期换行，不拆断日期中的月日；支持名称及摘要搜索、每页 20 条的游标分页、触底自动加载、下拉刷新和错误重试；搜索覆盖全部历程，切换搜索后重新分页。下拉手势与刷新提示仅作用于卡片结果区域，标题、搜索框和数量说明保持原位，空列表和读取失败时仍可下拉重试。触屏隐藏刷新按钮，PC 保留；加载更多失败后暂停自动重试，可点击重试。刷新与详情返回会重新读取已加载范围并整体更新，失败保留现有卡片。搜索保存在地址中，详情返回时保留搜索与列表滚动位置；切换成员清除旧数据，离开后忽略迟到响应。无历程时引导到记录详情关联，不提供单独新建历程入口。分页请求使用 `GET /api/health-processes?memberId&limit=20&q&cursor`，返回 `items`、`total`、`hasMore` 和 `nextCursor`；游标绑定成员及搜索条件，按最近记录时间与稳定 ID 翻页。未携带分页或搜索参数的旧请求仍返回摘要数组。内部 API 路径及表名保留，不涉及数据迁移。

### 记录详情与历程管理的边界

报告、影像、症状、用药及接种详情的“健康历程”统一仅展示所属历程名称、记录数量、日期范围与“查看历程”，不重复铺出同一历程全部记录、来源或管理操作；尚未形成历程时保留“关联记录”，用于首次建立关联。全部阶段记录、继续补充已有记录和历程记录管理集中在历程详情。“管理历程记录”按实际记录计数，每条只展示一次，包含类型图标、名称、类型与日期，不展示内部连线或重复的基准记录。

管理者可将某条记录“移出历程”，原始资料、用药、症状、接种及提醒独立保留，其余两条及以上记录继续留在同一历程并保留历程名称及手工阶段；仅剩一条时历程不再展示，返回来源页，两条原始记录仍在记录列表。服务端通过 `POST /api/health-processes/:id/records/remove` 校验成员权限、当前记录及历程内容版本，在事务中清理被移出记录的联系，只补齐其余记录之间必要的联系，并重算历程；不改变业务记录与来源关系，也不递增 schema。失败整体回滚，丢失响应重试不会重复移出。查看者不显示管理入口，成员切换后忽略旧响应；后台刷新不取消已打开的确认框，确认提交仍使用打开时的版本，内容变化时拒绝覆盖。

已有记录之间的连线仅作为兼容现有数据的内部实现；界面按历程成员理解和管理，不展示直接或间接关联、报告数量或连线计数。已有来源用药单、原件附件、所属用药及接种剂次仍保留各自业务语义，不自动代表历程归属。PC 历程时间轴卡片的类型图标为 40px，与记录列表一致；小屏（≤760px）或触屏保留 24px。此调整不改变既有结构和 schema 编号。


### 就诊摘要、体温小结与快速记录

`GET /api/health-processes/:id/care?timeZone=…` 在当前历程范围内读取原始症状、报告诊断、报告所列用药、已确认用药、实际服药与接种，返回可直接选中或复制的就诊摘要及便捷录入选项。不调用 AI、不持久化第二份临床数据，不因缺失内容补造病因、诊断或转归。摘要区分“报告所列用药（不代表已服用）”“已确认用药”“实际服药”，展示原始时间、机构和剂量；症状默认列最近三次变化，实际服药默认列最近二十次并标明节选、保留总次数及按日期和药品汇总的次数。“给医生看”打开独立就诊摘要弹窗，不在历程页面内展开；沿用共享弹窗外壳，触屏显示拖拽条，标题和底部复制操作固定，正文独立滚动并可选中文字。复制复用安全剪贴板及 HTTP 降级工具，失败提示手动选择复制；关闭按钮、遮罩或 Escape 关闭后返回入口并保留历程滚动位置。焦点限制在弹窗内，切换成员、历程或离开页面时关闭并释放滚动锁；打开摘要不额外请求或调用 AI。

体温小结仅识别名称明确包含体温、发热、发烧、低热或高热的症状中，已保存、未撤销且数值明确、单位为摄氏度的测量记录。展示最高值及时间、最近一次及时间、记录次数和覆盖日期数；“≥37.5℃ 的记录天数”按查看端时区去重日期，只表示记录达到该数值，不作诊断或用药依据，不推算未记录日期。普通数值症状、其他单位和文字性测量不混入统计。纠错、撤销、移出历程及回收站状态在重读时同步反映。

已有症状与药品以紧凑按钮展示，“再记一次”打开独立弹窗并带入名称与当前时间；症状补记变化、可选数值、单位、程度与说明，体温不预填上次测量值。药品可来自已确认用药、报告处方或已记录服药；仅带入上次实际服用量，不以处方剂量充当这次实际用量。不同规格与来源不按药名盲目合并，从处方记录一次服药不会自动确认开始一段用药。

`POST /api/health-processes/:id/quick-record` 校验当前成员、管理权限、历程内容版本、目标仍在历程、已发生时间和稳定请求编号。症状变化追加到原症状；实际服药在同一事务中保存并加入当前历程，保留原处方和用药方案。失败保留输入，重试不重复写入；保存后刷新小结与原历程，恢复按钮焦点。关闭保护未保存输入，成员切换、权限收回及页面离开关闭便捷弹窗并忽略迟到响应。查看者可查看摘要和体温，不显示录入按钮。

本功能复用既有结构，无版本及 schema 编号递增。


### 常用值与自由填写

用药新增、调整、单次服药、历程快速记录及报告用药校对，共用可输入的下拉控件：频次、用量单位、剂型、途径提供常用值；报告数量单位与用量单位分别提供选项。症状新增与编辑的出现频率、变化记录的测量单位使用同一交互。输入框可直接填写，右侧箭头选择常用值，“不填写”清空选填项。药品名称、实际用量、每次剂量、规格及描述仍按原方式填写。

常用项仅辅助录入，不自动选择或推算用法；报告带入的缩写、特殊单位及历史自定义文字原样显示、编辑和保存，不映射、换算或覆盖已有值。接口和数据格式不变，无版本及 schema 编号递增。


用药单的校对字段、OCR 与 PDF 查看统一放入顶部工具栏，窄屏按需换行；隐藏外部工具栏的嵌入场景保留正文操作。用药详情的当前记录操作集中在顶部 `record-detail-toolbar`：用药状态、记一次已服药、调整、暂停/恢复、停止及回收站统一布局；单次服药工具栏仅保留编辑与移入回收站。触屏将状态、服药操作与回收站保持为一行：状态“用药中”、入口“记服药/补记服药”，调整、暂停/恢复、停止保留文字并移除重复图标；正文与按钮字号不缩小，按钮扩展触摸区域。停止后仅提供补记入口。历史服药及用药详情中的服药列表同样仅提供编辑与回收站，移入单次服药后刷新当前列表，不关闭所属用药详情；确认、30 天保留、恢复与永久删除统一沿用共享回收站流程，不再提供“撤销服药”操作。沿用既有权限、确认、保存及弹窗流程。

### 三批照护能力

第一批：体温曲线与小结共用已确认的摄氏测量记录。常用症状首次保存时，在同一事务内建立独立症状、加入当前历程并追加变化；未保存不生成记录。保存并继续保留弹窗，沿用保存后的症状身份与历程内容版本，清空本次数值与说明，重置请求编号；失败重试保留原编号。就诊摘要支持按内容与按天排列，复制当前视图，按天超过 200 条时明确标注节选。两种摘要均区分处方、确认用药与实际服药，不调用 AI。

第二批：管理者可填写起病／开始日期、历程状态和结束日期，允许未知；不从最早／最晚记录、症状消失或停药推断起止。只有已结束可填写结束日期，日期不得在未来或倒置。元数据纳入编辑版本及成员合并确认校验。保留既有流程与时间视图。频次展示前后端共用函数，只解释明确匹配的缩写，保留原文，不改库或解释混合指令。

第三批：历程列表增加“按疾病／症状看”，不新增底部导航或创建入口。报告诊断与自述症状分开索引，同报告相同诊断只计一条来源；仅归并名称格式，不猜测医学同义词。支持搜索、分页、打开原记录及相关历程；报告所列药品注明不代表已服用。索引为只读派生查询，回收站及已删除记录排除，查看权限沿用成员访问权限，成员或页面切换忽略旧响应。

新增 `health_record_process_metadata` 为独立可选增量表，复用未编号结构草案；schema 保持 v19。旧库启动先备份再幂等补齐，备份失败停止启动，重复启动保留元数据和原记录。无正式迁移或应用版本递增。


### 按部位录入症状

新增症状先展示常见部位，更多部位按需展开；选择部位后只展示该部位的症状，初始“全身／不确定”不写入身体部位，也不默认严重程度、日期或其他症状。覆盖头部、五官、颈肩、胸腹、腰背、四肢、皮肤、泌尿与生殖部位、肛门，以及不局限部位的全身和睡眠／情绪表现；这是录入词表，不是疾病诊断或分诊规则。词汇参照 [NHS 症状目录](https://www.nhs.uk/symptoms/) 交叉核对，分类及中文词汇用于本项目的录入便利，不宣称是完整医学词典。

点击症状只填写名称，保存前不生成记录。切换部位时清除不再适用的快捷症状，自定义名称保留；收起更多部位后保留当前选中项。仅名称必填，不要求用户为全身或不明部位强行定位。开始日期可选今天、昨天或不确定，按查看端本地日期填写，未知仍保持为空。

补充信息提供具体位置（含左右侧和上下腹等）、严重程度、发生频率、诱因、缓解因素、可多选的伴随症状和自由描述。常用选项不自动推断病因、左右侧、程度或缓解效果；用户确认后才写入。伴随症状沿用原文本字段，多选可再次取消并保留其他自定义内容。所有内容复用既有字段、权限、未保存保护及重试编号，未调整接口、数据库或版本编号。

新增症状的部位与症状采用不同层级的选择样式，快捷症状排在自由输入之前。选择更多部位后自动收起且保留当前项；重复点击当前部位不覆盖已细化的位置。日期快捷项与标题同行，补充信息收起后显示已填写摘要（含程度 0），完整字段仍可展开修改。触屏保存区保留在底部导航上方，表单保留末尾滚动空间。


### 症状关联测量项（首项：体温）

新增症状使用共享 `symptom-measurements.ts` 配置可选测量项，按明确的主症状或伴随症状名称匹配字段、固定单位与数值格式，前后端共用配置。本轮仅启用体温：发热、发烧、体温、低热、高热；伴随症状按分隔符拆成独立词项后匹配，不通过“含有发热二字”等模糊匹配推断。主症状匹配时，体温填写紧跟症状名称，位于同名续记提示之前；仅伴随症状匹配时，在伴随标签下方展开并滚动到可见位置，两处同时匹配也只展示一组体温。其他症状提供“补充体温（选填）”入口，点击后显式填写，不依据症状推测数值。未来可增加明确的测量定义；新增数值类型、单位转换或统计能力仍需相应实现与验证，不因注册字段自动提供。

体温值默认空，单位为 ℃；显示字段时带入当前查看端本地测量时间，允许修改。测量时间与症状开始日期独立，开始日期未知时不由测量时间反填。不测量也可正常保存症状；清空数值后不创建测量记录。切换到不匹配的症状时，不发送隐藏测量草稿；切回可继续原草稿，切换成员时全部重置。

新增接口可选 `initialMeasurements: [{kind,value,recordedAt}]`，支持一个症状带多个已注册测量项，当前最多一个体温项。服务端校验匹配关系、重复项、数值格式、完整且已发生的测量时间，以及不得早于已知症状开始时间；固定单位由服务端配置决定。只记录原始测量，不据此推断发热程度或病因。症状、测量更新、关联与请求回执在同一事务中保存，失败回滚，响应丢失后的相同请求不重复创建。

测量复用既有 `health_process_symptom_updates`，症状详情直接展示最近一条未撤销的测量及其时间，历史可查看和修正，不由测量推算严重程度；关联历程后由现有体温小结、曲线和摘要读取。未关联历程时保留在症状变化中，后续关联即可纳入统计。无数据库结构、schema 编号或应用版本递增。

### 报告详情首次加载

普通报告与用药单详情通过 `health-records/documents/:id?includeDetail=true` 一次读取同次资料和当前报告完整详情，避免先读分组、再读详情的串行请求；不传此参数时仍只返回资料列表，接种凭证保留原有确认流程。详情组件仅在首次加载消费这份完整数据，继续校验报告及成员归属；切换资料、返回原资料和保存后的刷新重新读取当前数据，不保留跨次打开的详情缓存。正文读取使用 `includeDuplicateCandidates=false` 跳过跨报告重复比对，并保留原件、指标、专属内容与成员核对信息；原接口不传该参数时仍返回完整重复候选。待确认报告返回 `duplicateCandidatesPending`，正文显示后通过 `reports/:id/duplicate-candidates` 补齐重复候选；已归档报告不自动执行界面原本不展示的候选扫描。后台结果必须匹配当前报告、成员、sourceVersion 和 updatedAt，切换或刷新后旧响应不能回填；核对未完成或失败时保留明确状态及重试入口，确认归档等待核对完成，不把尚未比对当作没有重复。PDF 原件导出状态在后台更新，不阻塞详情加载完成提示。首次读取任务历史仅建立状态基线，已有的已完成或失败任务不触发第二次详情加载；之后任务真正变化仍自动同步。若首次任务状态表明当前处理中报告已完成，则补读最新详情；任务历史先于详情返回时，详情显示后仍按处理中状态恢复轮询。后台刷新保留现有内容，并使用“正在更新报告内容”提示，与首次“正在读取档案详情”区分。现有错误处理继续生效。

### 统一字号层级

页面、分区及弹窗标题使用 16px；正文、卡片主要内容和表单输入值使用 14px；日期、标签、字段名、状态及辅助说明使用 12px。统计数字、趋势数值和其他数据可视化数值保留独立尺寸，不作为正文缩放。表单的输入框、可填写下拉、选择器选项、日期输入及滚轮在 PC、触屏和紧凑筛选中统一为 14px，选中日期只改变字重与颜色，不通过缩放放大字号。紧凑筛选、次要操作及状态标签保留 12px，表单提交按钮使用 14px；保持既有紧凑操作栏高度与点击范围，不再引入 13px、15px 的局部文字覆盖。症状表单内嵌标签与输入框保持 7px 间距，与其他表单字段一致。部位、症状与伴随症状快选采用 28px 高度、左右 8px 内边距和横向与纵向均为 4px 的间距，部位使用 6px 圆角，症状保留胶囊形；快选标签文字统一为 12px，保留选中、键盘焦点状态。

PC 新增用药流程弹窗（入口、从报告带入、手动添加与单次服药）采用最大 600px 宽度，表单提示及字段间距收紧，内容超出可用高度时沿用正文滚动。既有用药详情宽度和触屏布局保持原有规则。

### 历程 AI 整理状态回显

历程详情将本次请求与服务端 `aiState` 统一回显在 AI 整理按钮上，不再单独展示重复状态说明。点击后按钮立即转圈并显示“正在整理…”，刷新或重新进入读取到 pending 时继续显示并轮询；完成后回填标题、摘要与阶段，按钮恢复“AI 整理”；失败时显示“重试 AI 整理”，并保留上一次有效整理内容。已有内容刷新时暂时禁用整理按钮，保留时间轴及阅读位置。

请求响应中断后重新查询实际状态，服务端仍运行时继续跟踪，不重复提交。后台读取与整理响应按成员、历程及页面上下文校验，较早的读取不能覆盖刚完成的结果。就诊摘要除原始记录指纹变化外，也在历程标题、摘要或编辑信息发生变化时重新读取，内容未变化的轮询不重复请求。后端优先返回同一批记录最近一次整理的失败状态，旧的成功缓存仍可供查看，不遮盖本次失败。无数据库结构或版本编号调整。

### 健康历程回收站

历程详情标题栏右侧沿用纯图标“移入回收站”，确认保留 30 天后返回来源页。“我的 → 回收站”统一提供恢复和永久删除。删除仅解除历程关联、保存历程快照，不触碰原报告、症状、用药、服药、接种、原件附件和提醒；永久删除及到期清理也仅清理历程与快照。

新增独立 `health_record_process_trash` 表保存标题、日期、节点阶段及关联快照、到期时间与修订号，历程自身的标题、摘要、状态和阶段元数据保留。沿用启动前备份和幂等建表机制，缺表检测已纳入启动检查，备份失败停止启动；schema 维持 v19，不新增正式迁移编号，应用版本不变。成员合并、成员数据导出和完整 SQLite 备份包含历程回收站。

恢复不会连带恢复原记录的回收站状态；至少有两条可用原记录才能恢复，已永久删除或不再属于当前成员的记录不纳入。原记录已有新的历程关联时拒绝恢复，保留双方状态，不自动合并或覆盖。恢复保留原历程身份及手动整理信息，补足存续记录之间的连接，原记录随后恢复时仍可加入该历程。删除使用内容及编辑校验和请求回执防止重复操作，恢复及永久删除使用回收站修订号防止过期操作。审计只记录对象标识和数量，不保存健康名称、描述或快照。

### 统一历程关联文案

报告、症状、用药、接种详情及新增表单的入口统一为“关联历程”，弹窗同名，并说明选择同一健康事项的相关记录以形成或加入健康历程。弹窗内的记录名称、类型、搜索和已选数量仍按实际选择对象表述。已选内容的调整入口使用“调整历程关联”，上传整理及连续症状补充提示同步历程表述。已有健康历程中的快捷菜单及补充操作弹窗使用“添加记录”，说明将所选记录加入当前历程；仅调整文案，不改变关联、创建及保存规则。

### 统一页面内容宽度

PC 页面统一由 AppShell 的 `.page-content` 管理最大宽度和横向留白：外层最大 1420px（包含两侧内边距），常规桌面每侧 34px，761～980px 每侧 24px。概览、记录、趋势、历程、上传、设置与新增表单均填满该容器，不再额外设置 1040px 或 760px 的居中页宽。页面内部的卡片分栏、搜索框和弹窗保留自身布局；760px 及以下的移动端页面每侧留白统一为 8px，不再在 390px 处单独覆盖。

## 0.2.15 升级基线

本轮按 0.2.15 正式版本升级，不将 0.3.0 中途方案当作已发布客户端。旧事件式复查、独立事件关联、资料过程关联、用药 `episodeIds/eventIds` 和早期症状回填均已撤除。新增结构不再创建相应闲置表；已有开发库中的表和记录不做破坏性清理，现行代码不依赖它们。真实 0.2.15 schema 快照覆盖原报告与提醒保留、升级前备份和重复启动。详细核对见[兼容性走查](0.3.0_COMPATIBILITY_AUDIT.md)。


### 记录—查看—纠错闭环

新增症状按名称格式精确查找已有记录（不合并医学同义词）。从历程进入时限定当前历程；选择关联记录时限定这些记录所在的历程及直接选择的症状；没有来源上下文时展示当前成员的历史同名记录。候选展示部位、开始日期、最近时间和状态，可分页加载。一个候选时主操作为续记，多个候选必须明确选择；“这是另一次不适，新建一条”仍可独立新建。查找尚未完成时提交会先等待结果，查找失败可重试或明确选择新建，不静默绕过。

续记打开独立弹窗，追加到用户选定的症状，不覆盖名称、部位、开始日期及其他基线资料。当前页已填写的体温、测量时间、程度和描述可带入；字段未填写时不带入历史测量值。保存时可同时确认原页选择的关联记录；失败整体回滚，相同请求重试不重复写入。续记成功后清空新增草稿并保留保存提示，“修改”直接编辑刚保存的变化。续记弹窗期间由弹窗保护未保存内容，取消后父表单的草稿和离开保护恢复。

历程内增加“变化明细”，按实际发生时间倒序读取症状变化、有效摄氏体温测量和实际服药，支持全部／症状／体温／服药筛选、数量和分页。处方及用药方案不会伪装成实际服药；已撤销、回收站及无访问权限的内容不进入明细。症状开始日期未知时仍以真实测量时间展示变化，不反填开始日期。保留原有流程阶段／时间视图，变化明细不是新的记录类型。

明细及保存提示的“修改”通过独立弹窗加载原笔记录和当前修订号，不新建替代记录。症状变化复用原纠错历史，服药复用原修订快照；服务端检查成员、权限、历程归属和修订号，过期提交不覆盖他人修改，相同请求可恢复丢失响应。删除或移出后旧入口失效。详情中的最近测量也可直接打开原笔纠错。

接口：`POST /api/symptoms/candidates` 为只读候选查询，`POST /api/symptoms/:id/observations` 追加变化；`GET /api/health-processes/:id/observations` 读取筛选后的明细；`GET/PATCH /api/health-observations/:kind/:id` 读取及纠错原笔，kind 仅为内部的 symptom/intake。查询及编辑均绑定当前成员，历程入口额外校验该记录仍属于当前历程。候选和明细分页绑定查询范围及当前源数据，发生变化后提示重新读取。

本轮复用症状变化、服药历史和已有请求回执，不增加表、迁移、schema 或应用版本编号；不增加 AI 调用或底部导航。

### 给医生看的事实汇总与背景

就诊摘要沿用既有“按内容／按天”和复制入口，不接入 AI。两种排列都包含成员姓名、已填写的性别及出生日期和当前查看时年龄、明确确认的起病／结束信息、本次诉求和重要健康背景。症状增加部位、发生频率、缓解因素及伴随症状；报告包含原有结论、印象、主诉、结论及建议类章节和原报告建议，保留报告名称、日期、机构和科室。相同内容只在同份报告内去重；不只挑异常结果，不从数值判断疾病，不把报告所列操作视为已经执行。较长内容明确标注节选并指向原记录；沿用症状最近三次、实际服药最近二十次和按天最近二百条的节选标记。

在成员信息中统一维护过敏及不良反应、重要病史和长期用药三个选填项。“给医生看”直接读取；缺失时仅展示缺少的项目，管理者可通过“补充成员信息”进入对应成员编辑，保存后回到原历程。摘要内仅保留“本次诉求”的填写入口。过敏及不良反应、重要病史、长期用药属于成员，其他历程共用；本次诉求只属于当前历程。空白显示“未填写”，明确无或不清楚由用户自行填写，不自动推断。长期用药文本明确标为用户补充，不修改处方、用药方案或实际服药；历程状态仍不能视为医生确认的痊愈。保留未保存保护、只读权限和失败重试；修改后刷新摘要，失败可重新读取。成员切换关闭原上下文，不应用迟到响应。

`PATCH /api/health-processes/:id/doctor-context` 使用当前成员、背景与诉求版本、稳定请求编号校验后原子保存。跨历程更新共用背景也会使旧版本失效，防止覆盖；重复请求可恢复回执。三个可空成员字段 `care_allergies/care_history/care_medications` 和历程元数据的可空 `visit_concern` 沿用启动补齐机制，缺结构前备份、失败停止启动、重复启动不覆盖数据，schema 保持 v19，不修改已发布迁移或应用版本。成员合并逐项选择保留背景，预览后背景变化会使合并失效；本次诉求随原历程元数据保留。完整数据库备份／恢复保留新增字段。旧客户端对可空独立字段的既有读写不受影响。

历程详情的“编辑信息与阶段”使用独立共享外壳弹窗，不在页面内展开。触屏保留拖拽条，标题与底部操作固定，字段和阶段列表独立滚动；关闭、遮罩及 Escape 共用未保存保护，保存失败保留草稿。取消或保存后恢复编辑入口焦点和原阅读位置；成员切换、权限收回或缓存页面离开时移除弹窗与滚动锁，不应用旧请求结果。接口及字段不变。

成员列表及创建／编辑接口补充 `careAllergies/careHistory/careMedications`，编辑背景携带 `careBackgroundVersion`，阻止过期表单覆盖其他历程或成员信息页的修改；普通基本资料更新不传背景字段时保留已有值。原有三个可空字段原地复用，无新增结构或迁移。摘要的诉求更新允许省略背景字段并保持原值；旧入口的完整请求继续兼容。成员编辑支持未保存保护、保存失败保留输入、权限收回及离开缓存页后关闭，不应用迟到响应。引导目标只接受当前账号可管理的成员，返回路径限定为应用内健康记录页面。

“复查与待办”的添加提醒改用共享独立弹窗，标题与底部保存操作固定、内容独立滚动，触屏保留拖拽条。核心字段仍为事项和计划日期，常用事项及 7／14／30 天后只在点击时填入，不自动推断复查安排。历程内可选择依据记录（名称及日期），保存沿用原有记录关联归入该历程，不提前创建医疗记录；完成后沿用上传或选择已有报告的流程。关闭、遮罩及 Escape 共用未保存保护，保存失败在弹窗内显示且保留草稿，保存期间阻止重复提交与关闭；离开缓存页或权限变化移除弹窗及滚动锁。无新增字段、接口、版本或 schema 编号。

### 历程首屏与最近记录

快速记录展示症状最近一次有效变化、测量值、程度及时间，药品展示匹配来源和规格的最近一次实际服药用量及时间；均标为“上次记录”，不推断当前症状、服药状态或漏服。已消失症状、已停用药品及只有服药历史的药品折叠到历史记录；新增症状通过右侧“新增症状”打开完整录入弹窗，与左侧历史记录入口同行；历史展开内容仍占满整行，无历史时新增入口保持右对齐。无变化时隐藏整个变化明细模块，筛选后无匹配但其他类别仍有数据时保留筛选入口。


历程中的复查与待办始终保留模块标题。没有提醒或紧凑列表中的提醒均已忽略时，展示“暂无复查与待办”，管理者仍可直接添加；查看者仅显示空状态。加载和失败分别显示读取提示与重试，不以整块隐藏替代空状态。

复查与待办的添加提醒入口统一保留在模块标题右侧，触屏不换到下一行；历程顶部“补充记录”菜单不重复提供提醒入口。点击标题右侧按钮打开新增弹窗。

症状与服药的追加操作统一以“新增”表述：症状入口及弹窗为“新增变化”，服药弹窗为“新增服药记录”，提交为“新增记录”，连续提交为“新增并继续”。历程快捷选项同步标明新增动作。修改已有条目使用“修改记录／保存修改”；症状基本信息编辑仍保存到原条目，不新增症状。此项仅调整文案，沿用原有新增、纠错接口及修订历史。


概览面板在 PC 使用统一的 48px 标题栏，标题右侧有无操作入口时分隔线保持对齐；触屏仍为 52px。PC 的资料处理三项统计使用紧凑同行布局，触屏保留 44px 两行点击区域；待处理资料卡片的日期保留卡片内边距，不沿用共享卡片的负边距。近期提醒使用左侧标题与日期、右侧垂直居中的操作入口，长内容可换行且不挤压操作；资料处理与近期提醒在 PC、触屏均按上下顺序排列，各自占满内容宽度；PC 资料处理与近期提醒内部的卡片均使用两列，只有一张卡片时铺满，资料骨架屏同步使用两列；触屏资料卡片及提醒列表保持单列。模块是否隐藏不影响上述排版，避免模块记录数量不同造成并排空白。

消息提醒仅保留查看来源、手工标记完成、忽略及恢复待处理等基础操作；移除消息中的记录复查、延期入口及跳转后自动展开业务操作的逻辑，不新增提醒详情页。历程内原有复查与待办功能保持不变。

历程“复查与待办”按计划日期升序显示待处理事项，默认前三条，可在当前模块展开全部；已完成与已忽略分别折叠，忽略后仍可恢复。卡片顶部展示事项与状态，下方为计划日期及依据记录，避免重复来源入口。记录复查先用独立弹窗选择上传新资料或已有报告，延期使用独立日期弹窗；手工标记完成与忽略直接展示，不使用“更多”折叠，操作区空间不足时自然换行；标题右侧保留添加提醒入口。沿用原有权限、关联、保存及未保存保护，不更改数据结构。

快速记录快捷按钮在桌面采用等宽两列，触屏使用单列；名称与新增操作分开排列，状态和上次记录使用辅助文字，长名称完整换行。常用症状预设在新增弹窗内展示，历史记录沿用相同布局；点击仍打开原有独立新增弹窗，移除超出按钮边界的点击覆盖层。


### 症状变化与附带体温

新增变化、快速记录和变化修改共用测量表单，沿用共享症状测量配置：发热等明确显示体温与固定 ℃；未配置专属测量项的头痛等症状不显示通用测量框，默认仅显示“补充体温”入口，点击后展开独立“附带体温（选填）”；修改已有附带体温时直接展示原值。无须填写体温即可记录症状变化，连续新增时清空上次体温。既有其他测量值仍可修改，与附带体温分别保存，不能仅凭单位推断旧记录是人体体温。

新增症状时也可携带首次体温，与症状和历程关联在同一事务内保存；非发热主症状使用附带体温字段，同名续记也正确带入附带体温及测量时间，不额外创建发热症状。附带体温写入原变化行的可空 temperature_value，时间沿用本次记录时间；不新增症状、不改变症状状态。有效附带体温与原有发热类摄氏测量共同进入历程体温统计、曲线、体温筛选及就诊摘要，同一变化只计一次；更正、清空、撤销后按有效原记录重算。服务端校验正数与成员权限，保存及重试沿用原事务与幂等键。

schema 编号保持不变，沿用 health-process-draft 的启动补齐：缺字段纳入结构修复检测，先备份，再在事务中补齐可空字段；重复启动不重复备份或改写数据，失败阻止启动。旧客户端可以继续读写原字段，但不会展示新增附带体温；新客户端兼容历史记录，不回填推断值。

历程内新增症状统一使用完整症状录入弹窗：快速记录与顶部补充记录菜单均打开同一表单，固定当前成员与历程，沿用部位、症状预设、测量、同名续记及失败草稿保护，保存沿用症状接口的事务关联，成功后关闭弹窗并刷新当前历程，不跳转记录详情。已有症状的新增变化保持独立变化弹窗；普通新增症状页面行为不变。

新增症状表单提示用于记录新出现的不适，已有症状加重、减轻或再次出现选择新增变化；变化新增弹窗提示仅补充当前症状，不新增症状记录。说明使用 12px 辅助文字，不新增确认步骤。

报告中的用药、接种事实保留在原件详情，分别通过确认实际使用与核对并记录形成独立记录，不由识别结果推定实际使用或接种。已确认接种提供查看入口；重新识别导致来源条目 ID 改变时，仅在同一来源、同成员、名称剂次日期完全一致且唯一时恢复查看关联，歧义不匹配。资料类型可通过独立弹窗仅提交类型和原版本号修改，失败保留选择；其他资料在本次上传中直接提供分类选择。分类修改不重跑 AI，不改写原件和其他字段，识别内容缺漏仍须核对或重识别。

概览模式的叙事路由除用药与续表页外，也保留明确接种标题或字段的页面；门诊、住院叙事契约允许接种数组，并明确本次日期、下次日期和批号的来源约束，不以文档主类型排除附件接种。跨页同编号药物要求单条输出并保留各页依据；无法证明同一条目的项目不自动合并。此项不开放影像入口，也不将报告原文自动确认为已用药或已接种。
