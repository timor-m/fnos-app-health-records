# 用药识别适配说明

## 分类与路由

文档分类与用药内容分别判断。门诊病历、出院小结和综合体检保留原文档类型；页面存在明确用药标题，或药品与用法、规格数量表格等组合证据时，标记为包含用药内容。识别不依赖医院名称或固定模板。

概览和详细模式都通过现有 `narrative` 路由提取用药，输出 `medications`；不新增数据库类型或迁移。概览只选择有用药证据的页面，详细模式仍保留其他叙事内容。混合文档不因用药只是次要类型而丢失药品输出契约。单元拆分重试保留用药标记。

## 成员归属核对

用药单沿用报告的本地身份核对，不依赖 AI 重跑。识别明确的姓名、患者姓名、用药人等标签及相邻 OCR 值；不将无标签人名或医生、药师姓名当作用药人。每页只读取最新 OCR。

“姓 / 名”和“性 / 别”被拆成相邻 OCR 单元时，只在文字框能确认属于同一字段时拼接标签，兼容横置原图坐标；无坐标文本只接受紧邻的完整标签片段，不跨字段搜索人名。不改写原始 OCR，也不拼接医生、药师或联系人等身份标签。

成员没有性别、生日也会进行姓名核对；姓名与成员称呼不同时请求确认，不能直接认定选错成员。姓名未可靠识别、现有患者信息又缺少可比对的成员资料时，显示“成员归属待核对”，不声明身份冲突。可确认属于当前成员、选择已有成员或创建成员归属；确认提醒不自动改动成员资料，重新归属后重新评估。

自动推荐不是完整成员列表。提醒中独立提供“选择已有成员”，仅列出当前用户有管理权限的其他成员；未选择时不能提交，选定后再确认归属，后端复核双方管理权限。无候选、暂无其他可管理成员及权限变化分别给出反馈，切换报告清空旧选择，不将旧确认应用于新报告。归属成功后关闭原成员下的详情并刷新列表，不在旧成员上下文重新读取已转移的报告；失败时保留详情供重试。创建成员后刷新成员列表，刷新失败单独提示，不将已成功归属误报为失败。成员归属、新建并归属、确认属于当前成员与确认归档互斥；异步完成或失败仅更新请求发起时的报告上下文，切走再返回同一报告也不复用旧确认。归属成功时使在途详情请求失效并隐藏旧摘要，避免关闭过程中重新显示已移走的资料。

成员核对回归覆盖姓名独立信号、标签分行/空格、医师及联系人排除、资料缺失、确认提醒和最新 OCR 选择。分别移除姓名提醒、资料不足提醒、最新 OCR 选择后，对应回归失败；既有报告 OCR 也验证了资料不足提示分支。新增拆分标签和手动成员选择回归；分别去掉标签拼接、将手动选择限制为有推荐时显示，对应回归失败。归属完成回归使用转移后返回目标成员的接口数据，覆盖关闭详情、写入失败及成员列表刷新失败；消融恢复旧成员下重新读取后，归属完成回归失败。补充异步完成、失败、切换报告、重复操作和旧详情晚返回回归；移除本轮互斥及上下文保护后，对应回归失败。沿用现有报告上下文计数、选择组件、归属接口和关闭事件，不新增接口、状态管理层或身份匹配服务。此验证不需要重新 OCR 或调用 AI。

## 中药汤剂

整张汤剂处方使用一个现有用药条目，各味药保存在结构化 `formula` 中；不新增药方表、药材字典或配方版本系统。字段包含剂数、煎制说明和逐味药名、用量、单位、口径（每剂/总量/未明示）、另列总量、配制说明及来源证据。整方的频次、途径、每次实际服用量沿用用药条目字段，不把药材投料克数带入服用剂量，不推算剂数与袋数的关系。

文字 AI 仍走现有 narrative 请求；一张方输出一个条目，中成药、西药继续独立输出。每味药均经过原文名称与证据核对，存在无法核实的成分时不静默保存残缺配方。同名不同配方不合并；重复扫描有 OCR 冲突时保留待核对并提示，不猜测真实药名或强行合并。没有新增自动 AI 重试。

确认整方使用、暂停、停用及记一次服药沿用现有用药流程，来源快照包含完整配方。校对来源药单或重新识别不会改写已经确认的用药/服用来源；实际配方改变时，通过新药单另行确认使用。手动校对和删除保护仍按完整来源身份生效。

本轮仅在现有 report_medications 增加可空 formula_json，沿用未发布的幂等结构补齐机制；缺列时先备份，补齐失败不继续启动。schema 编号与已发布迁移不变。原有单药列保持语义和读写方式，旧记录不自动猜测转换；较早客户端不能展示结构化配方，需使用新版查看，原文仍保留。验证覆盖新库、旧 v19 库、补齐前备份、失败中止和重复启动，以及整方入库、来源快照和普通单药回归。

消融分别移除配方归一化、逐味证据核对、来源配方读取和缺列检测后，对应回归均失败。保留共享配方结构与展示组件，未新增单独药方表、药材字典或配方版本系统。

## 场景与版式矩阵

| 场景或版式 | 分类依据 | 提取规则 |
| --- | --- | --- |
| 处方标题含空格、编号列表 | 处方标题或药品与用法组合 | 保留编号、药名及后续用法 |
| 无标题药品表 | 药品名称、规格、数量表头 | 允许提取明确规格数量，不推断剂量或频次 |
| 调剂单、配药单、发药单 | 单据标题与药材、饮片、代煎、处方或剂数组合 | 进入处方用药路径；每味投料量及小计保留原意，不推断实际服药 |
| 药名与用法分行 | 药品剂型与用法组合 | 只按明确连续上下文归属 |
| 门诊病历内用药表 | 病历标题及用药证据 | 保留门诊分类，按章节填写用药 context |
| 出院带药、出院用药表 | 出院文书及用药章节 | context 使用 discharge |
| 临时/长期医嘱 | 明确医嘱标题 | 即刻、必要时和频次缩写按原文保留 |
| 左右多栏表格 | OCR 保留的表头和列关系 | 每组药名与本组用法配对，不跨栏拼接 |
| 多页清单，无重复标题 | 前页用药证据及相邻页药品规格/用法 | 保留连续页；不跨缺失页推断 |
| 药名与用法跨页 | 相邻页连续上下文 | 分别保存来源页证据，归属不明的字段留空 |
| 体检中明确的当前用药 | 体检主类型及用药章节 | 保留体检分类，同时允许输出用药 |

续页规则会在无用药证据、页码不连续，或切换为检验、票据等内容时停止。不能依靠相邻关系把收费表或过敏史变成用药。

## 字段及误识别边界

- 药品名称、盐型、规格和剂型保留原文，不凭商品名猜通用名。
- 规格、每次剂量、数量、疗程分别提取，缺失字段不推算。
- 停用、暂停、调整和既往用药说明保留在 `instructions`，不得改写成当前服用；当前结构没有独立用药状态字段。
- 同名条目若剂量单位、频次、途径、疗程、数量或说明不同，不因名字相同而合并。
- 单纯收费明细、药品说明书、过敏史及泛泛的健康建议不作为用药事实。
- 临床事实继续通过 OCR 原文证据校验后入库，人工修改和删除保护沿用原流程。
- 调剂单中的药品克数、剂数与明确的单据元数据不进入检验指标候选；混合资料中的明确检验章节、结果/参考表格及浓度单位仍保留。横置调剂单只在多数文字框为竖长框、旋转后药名与用量配对明显增加时调整重建坐标，原件方向和来源坐标不变。
- 扫描 PDF 和图片中的明确横置调剂单还会在 OCR 阶段补一次像素方向纠正：标题所在边缘必须能唯一确定方向，纠正后须保留至少八成文字行、标题恢复横向且识别出更多用量才采用；异常或无改善沿用原 OCR，不循环尝试。新文字坐标映回原图后再进行现有行列重建，不用总量反推每剂用量，不增加 AI 重试。普通检验表和完整 PDF 文字层流程保持不变。
- 像素方向补识别覆盖双向横置、扫描 PDF、失败回退及混合检验资料；消融关闭该步骤后，图片与 PDF 回归均无法补回缺失用量，后续坐标重建不能替代这一步。
- 有调剂和克数证据却未产出可核实药品明细时，不得仅靠文档概况判定成功；保留原有结果，提示核对，不自动重复相同 AI 请求。

## 验证及限制

合成夹具位于 `packages/server/tests/fixtures/medication-layouts.ts`，不含真实患者或报告内容。测试覆盖上述 10 类场景、5 类反例，以及概览/详细两种模式的规划、跨页标记、请求契约、证据与持久化。模型响应由测试模拟；这些测试证明分类与数据链路能够承载相应内容，不证明真实模型对每种排版都能正确识别。

多栏支持依赖 OCR 保留可辨认的列关系；照片倾斜、药名模糊、手写内容和版面已被 OCR 错拼时，仍需核对。跨页条目若因请求预算或重试被分到不同单元，不强行补全缺失用法。药品字段目前没有逐字段的剂量核验机制，不能把原文匹配当作全部用法已自动核实，也不生成用药建议。

调剂单适配已在本地通过正常 OCR+AI 流程重跑，并核对用药分类、药品入库及检验指标排除；重复扫描导致的 OCR 药名、用量或说明差异仍需核对。合成回归覆盖横置双向、多栏、混合检验以及空结果拦截；分别去掉路由、剂量排除、横置适配和空结果保护会使对应回归失败。未执行 fnOS/Docker 安装验证。旧报告不会自动重跑，不改原件和人工校对记录。
