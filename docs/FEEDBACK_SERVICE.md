# 反馈服务接入

应用浏览器访问本地 `api/feedback/...`，由应用后端转发至统一网关服务（列表及详情使用 `/feedbacks`，截图上传使用 `/feedback-attachments`）。服务地址固定为 HTTPS，禁止跟随重定向，不转发本地 Cookie 或网关账号，转发时始终使用服务端保存的安装身份。所有本地反馈接口要求已登录，沿用现有 CSRF、维护模式及 fnOS / Docker 鉴权。

业务接口固定使用 `https://gateway.lby.link/health/v1`。截图仅按附件 ID 通过 `GET /health/v1/feedback-attachments/{id}` 鉴权读取：安装身份必须与附件及其已关联反馈归属一致；管理员须登录并拥有反馈查看权限。应用浏览器统一使用本地 `api/feedback/attachments/{id}`，本地后端检查登录并注入安装身份，不接受浏览器指定外部地址或身份；管理端携带 JWT 获取 Blob 后展示。完整静态地址与历史相对路径均不再用于展示，主截图和补充截图保持可见。图片响应仅接受 PNG/JPEG/WebP、最多 10 MiB，禁止重定向和缓存（`private, no-store`），凭据不放 URL。

远端复用文件及附件归属表，不搬迁、删除历史图片，不新增数据库迁移。必须在所有可能映射上传目录的域名中封闭 `/health/feedback/` 和 `/uploads/health/feedback/`，如有 CDN 同步拒绝路径并清理缓存；仅新增鉴权接口不能保护仍公开的旧链接。服务器规则见 next-admin 的 `deploy/next-admin/nginx/feedback-private.conf`。先部署远端鉴权接口与管理端，再同步更新应用并关闭旧公开入口；旧客户端需升级才能查看截图，列表和正文协议保持兼容。已下载或浏览器已缓存的图片无法撤回。

应用启动后检测安装标识（内部配置键 `x-client-id`），不存在时生成并持久化，再异步获取反馈列表。启动同步不阻塞正常使用；失败不弹窗、不提示错误、不记录日志。浏览器直接请求本地列表接口，无须先读取安装标识，也不提供 `x-client-id` 或 `x-version`；应用后端统一注入安装身份和当前运行版本。保留已登录的 `GET api/feedback/identity` 兼容接口，禁止缓存，该接口不访问远程服务。同一安装的本地用户共享反馈记录，界面明确提示。身份备份恢复规则见 [备份恢复](BACKUP_RESTORE.md#反馈安装身份)。

统一反馈服务按完整 `client_id` 唯一关联安装和反馈。首次有效访问反馈列表、上传或提交时登记（包括启动后台列表同步），通过 `x-version` 更新应用版本及版本上报时间；具有安装设备查看权限的管理员可在“查看环境”中查看完整标识。完整标识不放入反馈环境快照、日志或公开诊断，也不随普通反馈列表/详情返回。本地登录后的身份接口和管理端安装详情接口是授权读取完整标识的入口，均禁止缓存。

所有反馈请求统一发送 `HealthRecords/<版本> (<部署方式>; <系统>; <架构>)`，例如 `HealthRecords/0.2.12 (Docker; Linux; aarch64)` 或 `HealthRecords/0.2.12 (fnOS; Linux; x86_64)`。Docker 判断优先于宿主机或账号模式；本地账号模式本身不等于 Docker。开发环境使用 `Development`，不确定项使用 `Unknown`。系统为 Linux、macOS、Windows 或 Unknown，架构统一使用 x86_64、aarch64、x86、arm、riscv64、ppc64、s390x 或 Unknown；不附加安装 ID、账号、路径或浏览器原始 UA。

next-admin 的迁移 `089_health_installation_deployment.sql` 为安装记录增加 `deployment_type` 和 `deployment_reported_at`。服务只解析固定产品格式，保存最近一次有效的 Docker、fnOS 或开发环境类型；旧版 node/undici、未知或异常 UA 不覆盖已有值，也不因此拒绝请求。UA 不参与身份鉴权，版本仍以 x-version 为准；管理员访问不更新安装元数据。同一安装迁移部署方式后可刷新类型，历史记录不推测回填。先执行 next-admin 迁移并部署服务，再部署应用；旧服务会忽略新 UA。

支持列表分页与搜索、详情和处理记录分页、截图上传、提交、补充说明、确认解决和重新打开。列表及详情展示修复版本。POST 使用独立幂等键，当前页面内相同请求失败重试复用键；成功后清除。未提交草稿保留在当前页面内存，刷新会丢失。截图编辑只上传编辑后的文件，最大 6 张、每张 10 MiB；上传临时文件使用受限权限并清理。远程错误不显示假成功，不暴露上游响应或凭据。

指标问题池的“申请收录”进入“反馈与进度”并自动打开现有反馈填写弹窗，默认选择“其他反馈”，预填“指标字典收录申请（N 项）”及名称名单。生成名单时规范化去重，每批最多 40 个名称、单名称最多 120 字、正文最多 3000 字；疑似夹带结果、个人信息或无效内容时提示本地核对，超限须拆分，不静默截断。数字属于合法名称的常见写法（如 CA 125、维生素 B12、25 羟维生素D）保留。名称检查是保守规则，提交前仍需人工确认名单。

预填内容通过一次性内存草稿传递；URL 只携带 `compose=indicator`，不携带名单或报告信息，不写浏览器持久化存储。反馈页面首次打开及 KeepAlive 返回时均可接收；已有未提交草稿时先保留，用户可明确选择替换。关闭弹窗保留表单内容；刷新会丢失内存草稿，旧 URL 不会重新创建或自动提交申请。

后续完全沿用普通反馈：用户检查、修改、补充后主动提交，调用 `POST api/feedback/tickets`，自动加载和展示白名单系统环境，支持正常截图编辑上传、失败重试、成功编号和进度查看。不会自动附带报告、检查结果或截图，用户补充内容仍需遵守表单隐私提示。复用安装身份、幂等键及反馈状态基线，不增加指标专用提交接口。申请不会直接修改指标或问题池状态，也不会自动收录、更新字典或调用 AI；字典更新安装后的本地回填沿用现有机制。无需扩展远端分类或本地数据库结构。

列表每页 20 条，处理记录每页 10 条。列表、翻页及搜索将页码、每页数量和筛选条件传给 next-admin，每次只请求当前页；搜索由 next-admin 完成，不拉取全部反馈在本地筛选。成功返回的当前页同时比较本地状态：首次见到的反馈只建立基线，远程版本更高且状态变化时才生成管理员提醒，重复请求或旧版本不会重复提醒。翻页不触发完整同步；仅启动后台同步按每页 50 条获取完整列表，全部成功后才保存状态并生成提醒，避免部分失败更新基线。处理进度标题旁的刷新按钮在请求中旋转并禁用，成功后提示“处理进度已刷新”（进度不变也提示），失败时保留错误信息并允许重试。

提交前展示版本、部署、系统、OCR、AI 配置摘要与浏览器环境。按白名单组织结构化字段，不转发浏览器原始 UA、构建标识、账号、密钥、报告或检查结果；请求头 UA 由应用后端生成。描述和截图由用户主动提供，提交前提示遮挡隐私信息。

AI 摘要读取 `report_extraction` 场景的生效配置（含场景绑定覆盖），而非全局默认配置。保留 `enabled`、`visionEnabled`；AI 启用时附带 `provider`、`model`、`extractionDepth(overview/detailed)`，视觉启用时再附带 `visionModel`。未知或不可安全公开的值为 null；AI 关闭时不附带模型、服务商和解析程度，视觉关闭时不附带视觉模型。模型仅允许最长 120 字符的标识，过滤地址、路径、疑似密钥和 `ep-` 私有接入点标识；不收集配置名称、配置 ID、API 地址、密钥、提示词或健康数据。

提交前预览、本地已保存快照详情与远端管理端均按相同字段展示，并标注模型为“提交时配置”，不推断历史报告使用的模型。旧反馈只显示原有字段，不回填模型。诊断接口要求登录并禁止缓存；读取配置不调用 AI，不增加模型 token 消耗。先部署 next-admin 的扩展白名单与展示，再部署应用，否则旧服务会拒绝新字段。本次沿用 JSON 环境快照，无新增结构或迁移。

验证包括内存/文件 SQLite 身份持久化、完整备份恢复、H3 本地路由和模拟远程服务、Vue 交互测试。不自动向生产服务提交测试反馈。部署需使网关 `/health/v1/feedbacks` 可达；无身份请求应返回 401，404 表示需检查路由部署及代理。fnOS 与 Docker 上需继续验证真实网关访问、图片上传、私有图片查看和备份恢复。
