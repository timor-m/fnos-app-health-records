## 基线与判断规则

升级基线为当前已提交的 0.2.15（`f17f54d`）；该版本没有本轮新增的事件、症状跟踪、用药、接种或健康历程业务。0.3.2 已发布，当前开发版本为 0.3.3（Unreleased）。临时安装过的 0.3.0 和此前未发布的 0.3.1 只用于和后续安装包区分，不改变本核对的升级基线，也不把开发过程中更换过的页面、接口、字段含义当作需要长期支持的旧客户端或正式历史数据。

保留 0.2.15 已存在的报告、提醒、权限、原件、OCR、指标、备份恢复及数据库 schema v19 的升级能力。保留并发版本检查、原子保存、稳定请求编号和数据完整性校验；这些是当前流程的正确性要求。新增结构的首次补齐、补齐前备份及重复启动幂等也不属于业务兼容层。未操作用户数据库，不删除已有开发记录、不降号，不修改已发布迁移。

## 验收要求

- 对照基线确认每一项删除都不是 0.2.15 的必要升级路径。
- 当前五类记录、两两关联、历程分组与时间轴、用药来源、复查、接种剂次及回收站只有一套业务行为。
- 0.2.15 库升级与备份恢复、当前新库、重复启动、成员归属及权限验证通过；保留现有开发记录，不依赖假定发布过的中间版本。
- 更新相应测试为当前业务契约；旧功能测试随被撤除功能移除，原子性、权限、来源快照、备份及数据完整性检查继续覆盖。
- 完整服务端与 UI 测试、类型检查、构建及 `git diff --check`；最后再次扫描运行依赖和本轮新增的兼容分支。

## 必须保留的边界

- 0.2.15 的报告笔记、临床字段等写入未要求 `expectedSourceVersion`；省略版本时的协议兼容保留，0.3.0 表单正常提交版本以防并发覆盖。
- 0.2.15 已支持检查编辑的 1–100 字符请求标识；短标识原有的版本冲突语义需要保留，不将它误归为本轮旧客户端适配。新增长请求编号继续提供幂等重试。
- 生成标题和缓存标题共用质量校验，报告／用药单的记录身份归一化来自现行分类及引用模型，均不是中途版本兼容。
- 本地开发库存在已经保存的早期条目；本次只删除旧业务读写和新库创建，不删除表、不改原行、不补造来源、症状状态或删除日期。可空到期信息和提醒快照缺失时不自动删除或猜测前态，保留通用恢复保护；界面不再单独宣传“历史撤销”类型。
- 现行未编号草案的缺列补齐用于保护已落库开发数据，不串联版本号，也不产生第二套业务模型；缺结构前备份、补齐幂等、失败停止启动继续验证。

## 验证结果

- 直升保护补充唯一且禁止覆盖的私有快照、在线快照失败中止、包含 WAL 的一致快照校验及刷盘；完整备份共用同一快照入口。结构、版本设置及完成标记整体提交，补齐后校验，失败回滚并支持重试。测试覆盖同秒连续失败、补表后强制终止、SQLite 空间不足、后期字段补齐及完整性失败。
- 本轮升级加固新增 8 项针对性回归通过，服务端 `npm test` 全量 1408 项、`npm run typecheck`、`npm run build` 及暂存／未暂存差异检查通过。0.2.15 代码隔离演练逐表核对旧字段，原件、账号授权及有效本地会话保留正常，原版生成的完整备份在当前版本校验并恢复成功；该演练不等于 fnOS / Docker 安装包验收。Docker CLI 可用，但守护进程未运行，未启动或修改用户部署。
- 实际 0.2.15 代码隔离实验已验证完整备份可在新版本恢复；同时确认旧版报告归属修改会破坏新用药和历程的成员关联。后者没有通过机械升号或假定同号兼容消除，直接换回旧包继续写库不属于支持的恢复流程；安装及大库验收仍需执行。
- 真实 0.2.15 schema（从 `f17f54d` 生成，仅结构及迁移登记）升级、迁移前备份、原报告与提醒保留、无中途业务表、重复启动及症状无自动回填测试通过。
- 服务端完整测试 1368 项、UI 完整测试 792 项通过；最后的上传分组、入口移除及审计文案另做针对性回归。
- `npm run typecheck`、`npm run build`、`git diff --check` 及暂存区差异检查通过。已发布 `migrations.ts` 与基线逐字一致，应用版本保持工作区原有 0.3.0，schema 保持 v19。
- 运行代码不再引用上述被废弃的关联表、迁移标识或旧服药撤销状态。记录、报告、用药单的现行身份归一化和症状变化的纠错撤销仍按当前业务保留。
- 未进行 fnOS / Docker 安装验收，未进行真机触屏复验。未修改用户数据库、未提交、未发版。
