# 备份、恢复与迁移

健康报告原件、OCR 数据和 AI 配置都属于敏感数据。备份文件应保存在可信位置，建议加密并限制访问权限。

## 应用内完整备份

进入“我的 -> 备份与恢复”，创建完整备份。备份包含 SQLite 一致性快照、报告原件、分页图、缩略图、运行配置、AI 配置及加密凭据，并提供文件大小和 SHA-256 校验清单。

恢复前应用会自动创建一份“恢复前安全备份”。上传外部备份后，先执行校验，再确认恢复。大文件下载或上传失败时，参考[常见问题排查](./TROUBLESHOOTING.md)。

## Docker 数据备份

优先使用应用内完整备份。使用 Docker 数据卷备份时，先停止应用，避免复制正在写入的 SQLite：

```bash
docker compose stop health-records
docker run --rm \
  -v fnos-health-records-data:/data:ro \
  -v "$PWD":/backup alpine:3.22 \
  tar -C /data -czf /backup/fnos-health-records-data.tar.gz .
docker compose start health-records
```

如果使用 `DATA_HOST_PATH`，停止容器后备份该主机目录即可。不要只备份 `REPORTS_HOST_PATH`，它只是外部源报告目录，不包含应用数据库和已处理结果。

## 恢复和跨设备迁移

1. 确认目标版本支持备份中的数据库 schema。
2. 为目标实例创建一份当前安全备份。
3. 使用应用内恢复，或停止 Docker 后恢复数据目录/数据卷。
4. 启动应用并检查成员、报告、原件、趋势和 AI 配置。
5. 确认无误后再删除旧实例或旧备份。

fnOS 与 Docker 使用相同的业务数据格式，但认证方式不同。跨设备恢复保留当前系统维护登录路径；源成员权限不会自动授予当前管理员，必须显式核实身份映射。

## 回滚限制

新版本启动后可能执行数据库迁移。回滚前必须确认旧镜像或旧 `.fpk` 支持当前 schema；不支持时不要直接启动旧版本，应使用升级前备份恢复到独立实例验证。

## 0.2.10 未发布迭代：身份与授权恢复

恢复必须先预检再确认，内部备份与上传备份采用同一策略。确认凭据绑定备份摘要、当前恢复管理员、目标部署身份和已登记身份状态，15 分钟内有效且只能执行一次；备份或身份变化后重新预检。上传恢复需要预检和确认各上传一次同一文件。

- 同实例且操作者身份可验证：账号凭据、启停状态、成员授权、本人关联和隐藏偏好回到备份时点。管理员原来只有查看权限的，恢复后仍只能查看；普通账号不统一停用。当前已验证管理员的凭据和强制改密状态保留。备份后新增的账号、授权和状态可能消失，这不是合并。
- 同实例且操作者不在备份中：保留独立的系统维护账号，不给其成员权限。内部身份冲突不能当作同一人。
- 跨实例、跨认证模式或身份无法确认：源账号保留为待映射身份，旧登录不能用于目标部署；当前管理员仅保留系统维护身份。相同用户名、数值 UID 不证明同一人；fnOS 内部账号 ID 与网关 UID 已分离。
- 旧备份缺少部署元数据时，只有本地账号随机内部身份匹配才辅助确认为同实例；其他情况进入隔离映射。不会依据姓名猜测，也不会默认全部归管理员。

目标运行目录的 `deployment-identity.json` 是本地部署锚点，不随应用内业务备份恢复覆盖。不要把整个源数据卷直接当作跨设备身份迁移；新设备应建立目标实例，再使用应用内恢复与受控映射。实例标识不是凭证，也不能代替登录验证。

完整备份含数据库和密钥，持有完整备份或控制服务器的人可在应用外读取数据；管理员业务权限隔离不改变这个边界。

恢复会清除数据库中的登录会话和登录尝试，要求重新登录，不自动补建本人档案。当前版本拒绝在识别、归一化、维护、导出或其他请求尚未结束时恢复。切换前创建并验证安全备份，写入持久维护记录；文件或身份处理失败时恢复安全备份中的文件、数据库及授权。回滚失败或进程中断后保持维护状态，不开放半恢复数据。

### 跨实例映射与历史错误修复

参阅 [身份恢复维护工具](./IDENTITY_RECOVERY.md)。工具默认只读预览，需要核实源账号与目标账号实际持有人后逐项确认。映射不改写成员或报告的创建者、不移动报告、不合并同名档案；映射后在成员设置中自行确认本人关联、默认选择及个人隐藏设置。

### 恢复中断后的回滚

停止服务，保留运行目录 `restore-maintenance.json`、安全备份与 `.rollback-*` 目录。在仓库环境使用 Node 24：

```bash
node scripts/maintenance/restore-rollback.mjs --runtime /target/runtime --storage /target/archive
```

核对输出后，将本次摘要传给相同命令，并添加 `--apply --service-stopped --confirm 摘要`。工具校验安全备份、恢复数据库与文件，保留目标部署锚点与机器目录配置，成功后才移除维护标记。先在复制的数据目录验证；不要手工删除维护标记绕过恢复。

## 未完成的补充报告页

补充批次及检查点随数据库备份；文件和预览处于 reports/thumbnails，完整备份和存储迁移均覆盖。恢复继续保留原账号绑定和管理权限复核，身份待确认不会自动继续发布。已经完成的 OCR 不重复执行，AI 失败重试使用原任务检查点。详见 [补充报告页](REPORT_PAGE_APPEND.md)。
