# 多文件报告导入

单文件保持原有上传与识别流程。多文件先选择组织方式，再提交：

- **独立报告**：每个文件是一份报告；PDF 的内部页面仍归于同一份报告。
- **合并报告**：全部文件属于同一份报告，按列表顺序处理。
- **自定义分组**：每个文件夹是一份报告，支持移动、排序和图片预览；所有文件分组完成后才能提交。

浏览器上传、NAS 目录导入均支持以上方式。fnOS 直接授权多个文件后，也先整理再导入。NAS 文件权限仍按当前部署环境校验。

## 完整性与重试

浏览器按文件逐个传输，同时最多处理两份报告。整份报告的文件全部到齐后，才保存原件、创建报告并进入识别队列；不会将未传齐的报告交给 OCR。图片与 PDF 可以混合，PDF 按内部页序展开。

进度区区分上传失败与已保存；“已保存”不表示识别完成，可到档案查看后续识别状态。“重试失败报告”跳过本轮已传齐的文件；请求结果丢失时使用同一请求编号重试，不重复创建报告。NAS 源文件若已变化，需要重新选择导入。

上传期间请保持页面打开；目前不支持刷新页面后自动恢复任务，也不是单文件内的分片续传。已成功保存的报告不会因其他报告失败而撤销。放弃未完成任务会清理暂存，不删除已保存报告；超过七天未活动的暂存会在下次初始化上传时清理。

## 资源限制

不再限制每份报告只能包含 24 个文件。一次选择最多 1000 个文件，总大小最多 2GB，单文件最多 40MB；服务端也会校验每份报告的资源上限。图片很多时，建议按实际报告分组，不要把不同日期或成员的报告全部合并。

浏览器批量上传每次请求仅携带一个文件；反向代理仍需允许至少 42MB 请求体。NAS 导入不经过浏览器传输文件内容，但最终保存仍依赖磁盘空间，请为暂存、原件和后续渲染留足空间。
