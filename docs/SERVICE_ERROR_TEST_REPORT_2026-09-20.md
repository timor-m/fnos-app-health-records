## 额外发现：非根路径本地模式的首次改密拦截

**状态：已复现，未修复。**

触发组合：使用默认 fnOS 前缀构建产物，并以 `AUTH_MODE=local` 运行。新建本地管理员首次登录后，响应正确表明必须修改密码，但请求带应用前缀的成员接口得到 **200**，而不是预期的 **428**。

原因定位：`03-password-change.ts` 第 13–14 行直接检查原始请求路径是否以 `/api/` 开头，带应用前缀的路径无法命中。该文件相对基线提交没有改动。

官方 Dockerfile 和 Compose 均规定本地模式使用根路径构建及运行。本轮按该配置重新构建后，首次改密及其余 26 项 HTTP 检查全部通过；fnOS 网关模式不使用本地账号首次改密流程。最初非默认组合的失败仍保留在测试记录中，没有归入通过结果。

建议后续修复此路径兼容问题并补充带前缀的首次改密测试。现有验证不能用于承诺“任意路径前缀下的本地账号模式都正常”。
