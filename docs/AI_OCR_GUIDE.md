# OCR 与 AI 使用说明

## OCR

进入“我的 -> 运行与识别”安装 OCR 环境。OCR 环境保存在应用数据目录，升级或重建容器后会继续使用。PDF 会按页面处理；当文字层不完整时，会结合高清渲染图片再次识别。

OCR 失败不会删除已保存的原件。修复环境后可在报告详情中重试 OCR，或重新执行 OCR+AI。

表格进入 AI 前会按文字坐标恢复行列。对于同列相邻的两段指标名称，仅在拼接后唯一命中字典、右侧只有一个明确数值且无其它文字隔断时合并，并保留名称与结果的原始来源。多结果列、缺少坐标或归属不明确时保留原有处理，不强行拼接；复杂表格仍需对照原件校对。

## AI 配置

AI 在“我的 -> AI 配置”中设置。AI 连接以“连接配置”为单位管理：每份配置包含自定义名称、服务商预设、API 地址、Key 和模型，可添加任意多份；默认模型和“场景模型”都引用具体配置。支持常用 OpenAI-compatible Provider、MiniMax 和 Ollama 预设。视觉模型只应配置支持图片输入的模型，普通文本模型不能用于视觉任务。

“单次请求超时”控制每个报告解析单元等待 AI 返回的最长时间，默认 600 秒，可设置为 30～3600 秒。本地模型首次加载或 NAS 推理较慢时可适当提高；修改后新发起的解析任务生效。

MiniMax 选择内置预设后，中国大陆默认使用 `https://api.minimaxi.com/v1`，填写 API Key 即可使用默认的 `MiniMax-M2.7`。当前 MiniMax M2 系列在本应用中仅用于 OCR 文本整理，请保持视觉增强关闭；海外账号可将地址改为 `https://api.minimax.io/v1`。

`qwen2.5:7b` 可作为 Ollama 文本模型使用，但不能填写到视觉模型栏。首次测试前建议先执行 `ollama run qwen2.5:7b` 完成下载和冷启动；NAS 性能较低时，首次响应可能需要较长时间。长报告建议为模型提供至少 16K 上下文，Ollama 的 OpenAI-compatible API 不能在单次请求中调整上下文，需要通过 Modelfile 创建对应配置。

“自定义（OpenAI 兼容）”预设用于接入预设之外的 OpenAI 兼容平台（如硅基流动、OpenRouter、OneAPI 或自建网关），地址、模型名和 API Key 以平台控制台为准。同一个模型想同时挂在多个平台时，为每个平台各添加一份连接配置（可配置相同模型名），再用“场景模型”为不同场景指定使用哪份配置。旧版本按服务商保存的地址、模型和 Key 会在升级后自动迁移为对应的连接配置，场景绑定自动改为引用迁移后的配置，无需手工重新填写。

AI 结果会经过本地证据校验。无法回指 OCR 原文、单位不明确或来源存在冲突的结果不会默认进入趋势，但仍可在报告中查看和人工校对。

## 数据边界

发送 AI 前会过滤姓名、证件号、电话、地址、邮箱和精确出生日期等直接身份信息。原件、OCR 正文、报告结果和 AI 配置仍属于敏感数据，应根据 Provider 的隐私政策选择是否启用。

## 指标字典

核心和远程字典负责标准名称、别名、分类、指标类型和单位兼容规则。未命中的定量/定性项目进入管理员问题池，不会由 AI 自动创建标准指标。维护者确认后发布远程字典，管理员可检查更新并在本地回填历史指标。

形态发现、器官描述、查体部位、科室小结和报告叙事不属于趋势指标，不应为了减少未命中数量而加入指标字典。详细规则见[指标字典说明](../dictionary/README.md)。
