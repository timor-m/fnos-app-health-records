# 合并已有报告

报告详情的「合并报告」用于把分开上传、已经识别的多份单据补合并。当前打开的报告是保留目标，选择同一成员的另一份报告，查看预览后点击「确认合并」，再在明确提示中确认后保存；取消提示会返回预览，不修改报告。可搜索标题、医院或筛选同日报告；同一天仅为查找提示，不自动合并，也不等同于重复报告判定。

## 保存规则

- 目标保留原有标题、医院等基本字段。来源基本信息、结论及人工校对后的字段内容另存补充备注，长内容按现有备注长度分段，避免截断。
- 原件按目标现有页码追加，保留页 ID、原文件路径、文件内页码、OCR 和已有处理历史。指标、形态、诊断、用药、接种、收费明细、专属内容、备注附件、人工处理来源和提醒一起转移，不去重、不重新识别。
- 检查 ID、人工归属及已确认时间保持不变。未关联检查的旧指标和形态保留原报告展示日期的回退语义；没有日期时仍待确认，不借用目标日期。机构来自各自检查，避免跨机构趋势比较误用目标医院。
- 人工指标来源优先使用稳定页 ID；旧页码来源在重排前转换，已删除指标的抑制标记同时保留，避免重识别后恢复已删除项。
- 来源移入回收站，目标变为待确认。通过报告详情「撤销合并」恢复合并前的两份报告及原件、指标、校对、备注、检查时间和原有处理历史。普通回收站「恢复」不等同于撤销合并。
- 两份报告都有费用汇总或存在人工校对来源冲突时拒绝合并，避免静默丢失或混合票据金额。

## 撤销合并

- 在报告详情底部、补充记录下方，以同一行展示最近合并的来源、时间和「撤销合并」。支持撤销最近一次合并；连续合并须从最近一次逐次撤销。先展示将恢复的两份报告，再确认执行，取消不改变内容。
- 确认归档、阅读通知及提醒状态操作不阻碍撤销，通知与提醒的当前状态保留。合并后如又校对、补页、增删资料或重新识别，则提示暂停，防止覆盖后续内容；预览后发生修改也会在提交时再次拦截。
- 合并前的恢复快照保存在档案数据库专用恢复表，原件不复制、不重识别，不写入日志或发送至 AI。快照与合并在同一事务中保存；恢复失败整笔回滚。撤销成功后清除快照正文，仅保留操作元数据。
- 来源报告在回收站保留期间可撤销；永久删除来源或目标会同步删除恢复信息，不能再自动撤销。旧测试包未保存快照的合并不凭推测拆分，需核对合并前备份。
- 恢复表是向后兼容的独立结构，沿用启动前备份与幂等补齐；原报告表和 schema 版本不变。完整备份随 SQLite 保存恢复信息。

## 一致性与权限

两份报告均要求管理权限且属于同一成员。识别、补页任务进行中不可合并。预览指纹覆盖报告及保存内容，内容改变后须重新预览；合并在事务中完成，失败整体回滚。同一次确认使用固定请求标识，网络重试不会重复追加。

本功能不改变上传分组、原有重复报告治理和导航。恢复表由启动兼容补齐，不新增编号迁移。

## 验证边界

`report-combination.service.test.ts` 使用合成报告走上传、模拟 OCR/AI 的正常保存流程，检查原件与内容保留、日期与人工校对、再识别、事务回滚、权限、冲突及幂等。`report-combination.test.ts` 覆盖选择、预览、筛选、失败重试和弹窗交互。S0005 未提供报告附件，本地交互验证使用合成样本；不将其视为用户原报告或原 fnOS 环境验证。
